# Havenbox MVP 技术方案

版本：V0.3

日期：2026-10-25

依据：[MVP PRD V0.6](./product-requirements.md)

## 1. 设计目标

本方案只支持一条内部可用链路：一个内置 Agent 使用一个冻结的联网模型，在一个无网卡 Linux 虚拟机中调用预装 CSV CLI。

设计必须证明以下事实：

- 来宾不能直接访问宿主文件、宿主服务或网络。
- 模型只能收到用户批准的数据。
- 工具只能执行用户批准的固定调用。
- 原始输入保持不变。
- 停止和崩溃不会留下继续运行的任务。
- 重启不会自动重放请求或工具调用。

多 harness、本地模型、MCP 和多会话不属于本方案。现有候选代码可以保留，但不得进入 MVP 运行路径或发布资格判断。

## 2. 技术决策

| 项目 | MVP 决策 | 原因 |
| --- | --- | --- |
| 桌面应用 | SwiftUI 和 Swift 核心 | 仓库已有候选工程和存储实现 |
| 隔离 | 固定 QEMU/HVF Linux VM | 已有真实 VM 候选证据，且不把执行移到宿主 |
| Agent | Havenbox 内置状态机 | 避免三种外部协议、历史和旁路工具同时进入关键路径 |
| 模型 | 一个冻结的联网模型组合 | 当前已有 Keychain 和联网配置候选，本地模型仍缺真实资产验证 |
| 工具入口 | 固定 CLI 和 `CallPermit` | 仓库已有 CSV 引擎及 CLI 候选，MCP 不增加 MVP 用户价值 |
| 存储 | SQLite 3.51.3 和不可变文件对象 | 复用现有事务、迁移和事件实现 |
| 并发 | 全局一个活动任务 | 删除队列、跨会话和资源竞争设计 |
| 恢复 | 只读历史和中断标记 | 不恢复 Agent 内部状态，也不自动续跑 |

## 3. 系统结构

```text
Havenbox.app
├─ App UI
├─ WorkspaceStore
├─ FileBoundary
├─ TaskCoordinator
├─ BuiltinAgent
├─ ContextPolicy
├─ InferenceGateway
├─ CredentialStore
└─ RuntimeManager
        │
        │ control、file、inference 三条固定通道
        ▼
Linux VM
├─ hb-supervisor
├─ hb-cli
├─ hb-csv-engine
├─ /workspace/input   只读
├─ /workspace/output  可写
└─ /workspace/tmp     可写
```

宿主是可信控制层。来宾、模型响应、输入文件内容和工具输出均视为不可信数据。

### 3.1 宿主职责

宿主负责以下操作：

- 检查运行时、镜像、模型配置和凭据。
- 启动和停止 VM、模型请求及受管进程。
- 导入、校验、复制、预览和导出文件。
- 保存任务状态、审批、调用和成果索引。
- 生成披露材料、任务快照、网关凭证和 `CallPermit`。
- 校验来宾请求、模型出口和成果提交。

宿主不能把任意文件路径、命令、环境变量或模型地址交给来宾。

### 3.2 来宾职责

来宾负责以下操作：

- 校验通道握手、epoch、任务标识和消息上限。
- 在受限进程环境中运行固定 CLI。
- 使用 `FileId` 解析受控 staging 文件。
- 执行确定性 CSV 计算。
- 记录调用开始、终态和成果摘要。
- 在取消、超时或租约失效时清理任务进程组。

来宾没有网络设备，也不持有上游 API Key。

## 4. 核心对象

MVP 使用以下对象：

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| `Workspace` | `id`、`epoch`、`state` | MVP 只有一个 |
| `Task` | `id`、`state`、`configurationRevision`、`planDigest` | 同一时刻只有一个活动任务 |
| `InputFile` | `fileId`、`hash`、`size`、`mediaType` | 内容不可变 |
| `Disclosure` | `taskId`、`contextRevision`、`items`、`decision` | 批准后才能请求模型 |
| `Plan` | `taskId`、`revision`、`steps`、`outputs` | 任何改变都使旧批准失效 |
| `CallPermit` | 调用绑定、参数摘要、期限和上限 | 一次性使用，默认拒绝 |
| `ToolCall` | `callId`、状态、退出码和成果摘要 | 派发前落库 |
| `Artifact` | `fileId`、`hash`、类型和来源 | 校验后发布 |
| `Event` | `epoch`、`sequence`、类型和安全载荷 | UI 按游标读取 |

MVP 不创建会话、消息搜索、归档、跨会话引用或原生 harness 会话映射。用户输入作为任务请求保存。

## 5. 任务流程

```text
Draft
  -> Validating
  -> AwaitingDisclosure
  -> Planning
  -> AwaitingPlan
  -> Executing
  -> Summarizing
  -> Completed
```

所有非终态都可以进入 `Stopping`、`Failed` 或 `Interrupted`。`Stopping` 只有在网关请求和受管进程都结束后才能进入 `Stopped`。清理无法确认时进入 `CleanupFailed`，并继续占用全局活动槽。

### 5.1 创建任务

`TaskCoordinator` 先检查全局活动槽，再保存配置快照和输入引用。配置快照只包含冻结的 provider、endpoint、protocol、model、工具版本和资源上限。快照保存凭据引用，不保存 Key。

### 5.2 数据披露

`ContextPolicy` 从用户请求、CSV 元数据和用户选择的有限样例生成有序材料。每项材料包含来源、哈希、序列化版本和字节数。

用户批准后，`ContextPolicy` 保存不可变 `Disclosure`。`InferenceGateway` 只接受匹配任务、epoch、配置和上下文版本的短期凭证。披露改变后，旧凭证立即失效。

### 5.3 规划

`BuiltinAgent` 只接受固定工具 schema。模型可以返回澄清问题或声明式计划。宿主拒绝未知工具、未知字段、任意表达式和宿主路径。

计划卡展示输入、步骤、筛选条件、分组字段和输出。用户批准时，宿主保存计划摘要。参数发生任何变化时，宿主要求重新批准。

### 5.4 工具执行

宿主为每一步创建一次性 `CallPermit`。许可绑定任务、计划、工具、参数、输入、预期成果、epoch、期限和资源上限。

Supervisor 先登记调用，再执行 CLI。CLI 从固定模板生成参数数组，清空环境，并使用受控工作目录。CLI 不解释 shell 字符串。

CSV 引擎返回结构化事实和成果。Supervisor 校验退出状态、输出上限、内容哈希、CSV 结构和行数。任何校验失败都丢弃暂存成果。

### 5.5 总结

模型只能接收用户已批准的工具事实。报告中的数字必须引用工具事实。额外工具结果超出披露范围时，任务再次等待用户批准。

## 6. 文件设计

### 6.1 导入

宿主使用文件描述符读取用户选择的文件，并检查文件类型、大小和稳定身份。宿主拒绝目录、符号链接、特殊文件和读取期间发生替换的文件。

宿主计算哈希并创建不可变输入版本。文件通过有界分块通道传入来宾。来宾完成接收和哈希校验后，才将输入挂载到只读区。

### 6.2 成果提交

工具先写临时文件并关闭文件句柄。Supervisor 校验内容后，将文件原子移动到输出对象目录，并记录提交日志。宿主收到清单后，在一个数据库事务中保存成果和事件。

来宾已有文件但宿主事务未提交时，启动核查可以认领哈希匹配的成果。无法确认的成果不得显示为成功，也不得触发自动重跑。

### 6.3 预览与导出

CSV 预览按页读取，并把单元格作为纯文本显示。Markdown 渲染器禁用 HTML、脚本和远程资源。日志和文本预览移除终端控制序列。

导出通过宿主保存面板完成。宿主在写入前再次检查目标和符号链接。已有目标需要用户确认。写入使用同目录临时文件和原子替换。

## 7. 推理网关

MVP 网关只实现一个冻结协议和端点，不提供通用代理能力。

网关执行以下校验：

- 凭证绑定当前任务、epoch、模型、上下文版本、期限和预算。
- 请求方法、路径、模型字段和认证头由宿主生成。
- 来宾不能传入 URL、`Host`、`Authorization`、代理或重定向设置。
- 请求大小、调用次数、并发和超时使用任务快照中的限制。
- TLS 或网络错误不触发自动重试。
- 用户停止任务时，网关拒绝新请求并取消在途请求。

网关日志只保存版本、计数、状态和错误引用。网关不保存完整提示词、CSV 内容或 API Key。

## 8. 停止与恢复

`TaskCoordinator` 先把任务改为 `Stopping`，撤销网关凭证和未使用许可。随后，宿主取消模型流，Supervisor 终止任务进程组和 cgroup。租约失效也执行相同清理。

系统确认以下条件后释放活动槽：

- 没有在途模型请求。
- 来宾任务 cgroup 为空。
- 临时输出已关闭或登记为未知。
- 宿主受管进程已经退出。

应用启动时增加 workspace epoch，使旧凭证和许可失效。系统将未完成任务标记为 `Interrupted`，然后核查成果日志。系统不重发模型请求，不重新派发工具，也不继续模型对话。

## 9. 存储

现有 `WorkspaceStore` 和 SQLite schema 可以保留多会话所需的表，但 MVP 代码只使用单工作空间和单任务入口。未使用的表不能使延期能力出现在 UI 或发布验收中。

写入按以下规则执行：

- 一个宿主 actor 串行写数据库。
- 状态变化和对应事件在同一事务提交。
- 工具调用意图在派发前持久化。
- SQLite 开启外键、WAL 和 `synchronous=FULL`。
- 备份使用 SQLite backup API。
- 迁移失败后只开放只读历史，不启动任务。

重置先撤销凭证并停止任务，再关闭数据库和 VM。宿主把工作目录移入受管待删除目录，然后创建新 epoch。重置不删除宿主原件、已导出文件、运行时和独立 Keychain 凭据。

## 10. 安全校验

MVP 验收必须执行真实行为测试，不用提示词或模拟结果替代边界证明。

| 边界 | 必须取得的证据 |
| --- | --- |
| VM 拓扑 | 无网卡、无共享目录、无来宾可达管理接口 |
| 文件 | 宿主探针、路径穿越、符号链接、特殊文件和替换竞争均失败 |
| 工具 | 任意 executable、shell、参数变化、环境注入和许可重放均失败 |
| 网关 | 未授权请求为零，实际出口与批准材料一致，Key 不进入来宾 |
| 停止 | 正常停止、超时、失联和强杀后无任务进程 |
| 恢复 | 中断任务不重发、不重跑、不显示伪成功 |
| 预览与导出 | 脚本、远程资源、控制序列、公式风险和目标链接均受控 |

## 12. 实施顺序

1. 更新清单、任务图和唯一组合配置。
2. 在无 UI 条件下跑通模型、审批、真实 VM、CLI 和成果提交。
3. 接入文件导入、停止、重启核查和诊断。
4. 实现桌面主流程。
5. 执行安全与故障测试。
6. 生成内部包并完成用户试用。

详细任务见[执行计划](./development-tasks.md)。

## 13. 未解决风险

以下风险必须在对应阶段关闭：

- 冻结的联网模型能否稳定生成有效计划。
- 推理通道是否能在无网卡 VM 中稳定串流和取消。
- CLI 候选能否在 Linux guest 中使用真实 CSV executable 完成成果链。
- 宿主许可注册表能否跨重启拒绝重放。
- 参考设备能否同时承载 VM、桌面应用和模型流。
- 内部包能否无需终端完成运行时准备。

任一风险失败时，团队修复方案或停止 MVP 交付。团队不能通过开放宿主执行、隐藏失败或放宽安全检查来通过验收。
