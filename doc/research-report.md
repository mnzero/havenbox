# 桌面级 Agent 安全工作空间：产品与竞品调研

更新日期：2026-10-23  
状态：初步调研，供产品决策与后续验证使用  
关联文档：[产品需求文档](./product-requirements.md)

## 1. 调研结论

产品应定位为一台用户无需管理的 AI 专用电脑：以虚拟机级隔离为底座，通过普通桌面应用提供 Agent 运行、文件管理、模型调用和环境恢复能力。

直接对标对象是桌面虚拟化、应用沙箱及 Agent 运行环境。WPS、通用 AI 助手、RPA 是任务层面的替代方案，不是本产品的主要形态竞品。

当前 MVP 只使用内置 Agent、一个冻结的联网模型组合和确定性 CSV CLI。文件计算保留在隔离空间；联网模型通过宿主凭据代理和任务授权使用。Kimi CLI、Pi、dsh、本地模型、MCP 和更多认证方式是后续候选。具体边界和验收以 PRD 为准。

## 2. 调研依据与证据限制

初稿根据产品讨论及已知产品定位整理，当时实时检索未成功。2026-10-23 补查了第 11 节列明的 harness 官方接口和配置文档；其他竞品条目未因此完成核实。未进行产品安装实测、性能测量或安全审计。

## 3. 从第一性原理理解需求

Agent 完成工作需要读取数据、运行程序、连接服务。风险可能来自模型误判、提示注入、下载的依赖或恶意工具，因此应将整个执行环境视为不可信。

| 基本事实 | 产品推论 |
| --- | --- |
| 用户需要授予执行权限，但无法审查每一步 | 通过隔离与能力限制约束最坏影响 |
| 工作必须接触文件 | 建立明确的导入、内部流转和导出边界 |
| 工作状态需要延续 | 环境应持久化，不只是用完销毁的临时沙箱 |
| 访问外部服务需要认证 | 服务使用权与真实凭据分离 |
| 普通用户无法维护虚拟机 | 隐藏系统、网络和依赖管理，保留必要授权提示 |
| 本地模型可以减少外传 | 提供离线模式，但仍需要防误操作和结果校验 |

“无感虚拟机”指用户不管理虚拟机，不代表隐藏数据传输、文件导出或破坏性操作。

## 4. 中国市场目标用户

核心用户是假设中的一类非技术早期使用者：希望让 Agent 操作文件或执行任务，但不愿直接开放主电脑，也不想学习虚拟机、容器和 MCP 配置。

潜在场景包括运营资料整理、多来源表格汇总、内容素材处理和敏感本地文件分析。首版优先 CSV 文件处理，因为输入输出清晰、结果可核对，且不依赖业务平台接入。

以下问题尚未得到市场验证：

- 有多少用户因安全顾虑或环境配置困难放弃使用 Agent？
- 用户更愿意安装独立工作空间，还是使用现有应用的内置保护？
- 在任务效果相近时，离线与隔离能否带来付费意愿？
- 目标用户的设备是否能承受模型、宿主系统和虚拟机同时运行？

不宜把所有普通办公用户都当作首批用户，也不能将安全需求自动等同于购买意愿。

## 5. 竞品与替代方案

| 对象 | 对标价值 | 初步优势 | 相对本产品目标的待验证缺口 |
| --- | --- | --- | --- |
| Windows Sandbox | 临时隔离运行的系统级入口 | 独立环境、用完可销毁 | 支持版本、状态持久化、普通用户文件流转和 Agent 授权体验 |
| Sandboxie Plus | 日常应用级隔离 | 可配置规则、保留应用使用状态 | 普通用户规则理解成本、Agent 兼容及凭据代理 |
| Parallels、VMware、VirtualBox | 独立系统与持久化环境 | 系统隔离、应用兼容和环境管理能力 | 资源成本、初始化及长期维护成本；需逐产品核实 |
| 虚拟机无缝应用模式 | 隐藏虚拟机桌面的交互参考 | 将来宾应用呈现为桌面应用 | 当前版本支持、Linux 来宾适配及 Agent 工作区整合 |
| Docker Desktop Sandboxes 与 MCP Toolkit/Gateway | Agent 运行与连接器管理 | 与 Agent 和 MCP 场景接近 | 两套能力如何衔接、真实凭据边界、终端用户配置成本 |
| Claude Code 与 Codex 原生沙箱 | 应用自身的执行约束 | 与各自工作流集成 | 跨 Agent 的统一权限、持久工作空间及桌面文件体验 |
| 云电脑与云端 Agent 工作空间 | 环境及数据集中管理 | 终端无需承担全部计算 | 无网使用、本地隐私、延迟、持续成本和本地文件流转 |
| 国内安全软件的沙箱或隔离功能 | 本地分发渠道与安全认知 | 用户熟悉、安全品牌和触达能力 | 需确认具体产品及当前功能，不推定已有完整 Agent 方案 |

研究优先级：Docker 的 Agent 工具链、成熟桌面虚拟化、Windows Sandbox/Sandboxie、Agent 原生隔离。

## 6. 区分三种安全承诺

### 6.1 执行隔离

Agent 默认不能访问宿主文件、控制接口和局域网服务。虚拟机提供底层边界，但共享目录、剪贴板、网络和管理通道可能重新扩大攻击面，必须单独控制。

### 6.2 凭据隔离

| 方式 | 安全含义 |
| --- | --- |
| 自动将 key 写入沙箱 | 用户免配置，但 Agent 仍可读取真实 key |
| 注入短期限权 token | 减少泄露影响，但 token 有效期内仍可被滥用 |
| 沙箱外连接器持有上游凭据 | 最符合目标，仍需限制 Agent 可调用的动作 |

需要真实凭据的 MCP server 若与 Agent 处于同一可控环境，就不能仅凭“用户没填 key”宣称凭据隔离。浏览器在沙箱内登录也会产生可被访问的会话凭据。

拿不到密钥不等于无法滥用授权。例如 Agent 可以通过已授权工具发送消息，因此还需动作限制、撤销与高影响操作确认。

### 6.3 数据本地化

本地模型允许推理和文件处理不依赖云端。它不自动保证无外联、不自动保证数据安全，也不能防止错误计算或本地误删。

要宣称离线模式，应预置模型和依赖、关闭遥测与远程日志、禁止自动云端回退，并验证网络行为。

## 7. 本地小模型的机会与约束

建议采用“模型理解意图，确定性工具处理数据”的架构。

| 任务 | 初步判断 |
| --- | --- |
| 分类、提取、简单格式转换 | 适合作为候选场景 |
| 调用预置 CSV 工具汇总和筛选 | 适合首版验证 |
| 自主编写复杂代码、多步排错 | 不宜直接承诺稳定性 |
| 任意应用自动化、开放式长任务 | 超出首版范围 |

4B～8B 量化模型可作为候选，最终依据工具调用成功率、任务正确率、内存和时延选择。参数量不能直接推导可用性。

在 Apple Silicon 上，宿主侧运行模型通常更便于利用硬件加速。模型服务只提供推理，不提供宿主文件或命令工具；Agent 与文件操作仍留在虚拟机内。

代价包括更大的资源包、更高硬件要求和更窄任务能力。首次资源准备是否联网，需要与运行期离线分开说明。

## 8. 差异化方向

| 用户感知 | 底层能力 |
| --- | --- |
| 安装后直接开始 | 自动管理隔离运行时 |
| 只处理我导入的资料 | 不共享主目录，显式文件传输 |
| 原文件不变 | 导入副本与输入只读 |
| 关掉再开还在 | 持久化工作磁盘 |
| 不联网也能完成任务 | 本地模型与预置工具 |
| 可以立即停止、清空 | 任务进程管理与空间重置 |
| 以后连接账号也不暴露真实 key | 沙箱外受限凭据代理 |

竞争优势需要来自完整体验和可验证边界，而不是“使用了虚拟机”这一技术选型。

## 9. 验证计划

### 竞品实测

统一设备与任务，记录初始化步骤、首次任务耗时、内存磁盘占用、持久化、停止恢复、文件流转及网络行为。

以被攻陷执行环境的视角验证越权读文件、访问宿主服务、绕过网络限制、滥用代理和通过文件接口越界。安全结论必须标明测试版本和配置。

### 后续扩展验证

MVP 通过后，再固定 Kimi CLI、Pi、dsh 的版本，并分别验证会话接口和联网模型组合。本地模型需要单独完成物理断网、资源和工具调用验收。MCP 需要验证发现、调用、权限、停止和进程清理。所有扩展仍须证明宿主代理持有上游密钥，并且来宾不能绕过授权。

### 用户验证

邀请至少 3 位非技术用户完成一次真实 CSV 任务，观察是否需要终端或现场指导，能否理解数据边界，能否独立停止、导出和清空。

### 模型验证

建立固定样例，覆盖正常数据、字段缺失、非法数值和含指令文本的单元格。分别统计理解正确率、工具调用正确率、最终结果正确率、时延与资源占用。

## 11. Harness 与模型配置补充核查

核查日期为 2026-10-23。本轮只核对官方文档与仓库中的接口说明，尚未运行这些产品。Havenbox 的代理、安全策略和兼容矩阵是待实现要求，不能从上游支持自定义模型直接推导已经适配成功。

- Kimi CLI 提供 ACP 集成接口；模型提供方与模型分别配置，可配置不同推理协议。依据：[ACP](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-acp)、[模型提供方](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/providers)、[独立配置目录](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)。
- Pi 提供 RPC 子进程接口，支持本地及兼容端点模型配置。MCP 工具如何注册须按选定版本的扩展能力验证，不直接假设原生支持。依据：[RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)、[模型配置](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)。
- `dsh` 指 DeepSeek Harness。其架构提供 SDK JSON-RPC profile，模型配置包含第三方及自定义提供方；插件组合须受管，不能照搬默认权限。依据：[架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[模型提供方](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)。

产品推论：harness 选择与模型选择应独立。接口兼容、流式输出、工具调用和停止能力须按组合验证。联网模式不依赖先安装本地模型，本地模型也不能被当作对联网模型的默认安全过滤器。具体配置对象、代理约束、动线及验收已写入 PRD 第 6、7、9、13 节。
