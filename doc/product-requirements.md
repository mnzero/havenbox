## 1. 产品定义

产品是一款桌面应用，为用户提供无需管理虚拟机的独立 AI 工作环境。

用户导入文件、用自然语言描述任务、查看结果并导出。程序执行和文件处理留在本机隔离空间；模型推理可选择宿主本地模型或经授权的联网模型。底层隔离环境的创建、启动和维护由产品自动完成。

核心价值：让普通用户放心使用具备执行能力的 AI，同时限制它对主电脑、文件和外部网络的影响。

本期实现 Kimi CLI、Pi、DeepSeek Harness（dsh）接入、多轮会话与历史恢复、本地与联网模型配置、MCP 及 CLI。用户独立选择执行任务的 harness 和提供推理的模型，再绑定工具与数据权限。离线模式保留为完整可用路径，联网模型由用户显式配置和授权，不自动回退。

## 2. 产品原则

| 基本事实 | 产品原则 |
| --- | --- |
| Agent、模型输出及执行程序都可能不可信 | 执行环境与宿主隔离，不能依赖模型自觉遵守权限 |
| 工作需要读取和修改资料 | 文件通过显式导入、导出跨越边界 |
| 小模型处理复杂任务的可靠性有限 | 模型理解意图，确定性工具负责计算与文件操作 |
| 普通用户不应管理运行环境 | 隐藏虚拟机、端口、系统镜像和依赖配置 |
| 本地与联网推理的数据边界不同 | 离线模式不外传；联网前明确服务商、发送范围和授权，不自动切换 |
| 离线不能防止误删和错误结果 | 保留输入、限制写入、提供预览和明确确认 |

优先级：隔离边界成立 → 任务结果可靠 → 使用便捷 → 扩大兼容范围。

“无感”指无需管理虚拟机，不代表隐藏导出、清空等重要操作。

## 3. 用户与场景

### 3.1 目标用户

需要处理本地资料、重视隐私，但不熟悉虚拟机或 Agent 配置的非技术早期用户。初版用户需有符合要求的测试设备，能够安装应用、选择文件和检查结果。

### 3.2 首发场景

用户导入多份 CSV，要求按指定字段汇总数据、筛选异常记录并生成报告。用户可选择完全本地处理，或批准向指定联网模型发送任务上下文。两种模式的文件计算均在隔离空间中完成，原文件不被修改，用户预览后导出成果。

支持的操作：查看结构与字段、同名字段纵向合并、条件筛选、分组计数求和、规则异常筛选、输出 CSV 和 Markdown 报告。

异常必须有明确规则，例如金额小于零或订单号重复，不支持未定义业务标准的自主判断。

### 3.3 非目标

- 任意电脑操作、浏览器自动化。
- 复杂编码、自主安装依赖，以及绕过 CLI 权限策略的任意代码执行。
- Excel 公式、宏、PDF OCR。
- 远程 MCP、模型服务以外的业务账号登录和外部系统操作。
- 首版暂不接入订阅账号 OAuth 与 harness 托管登录，联网模型先通过可代理的 API Key 接入。
- 任意开放式任务的自主 Agent。

## 4. 方向与初版范围

| 能力 | 初版 | 后续方向 |
| --- | --- | --- |
| 工作空间 | 一个持久化空间，多会话与历史恢复 | 多空间、工作磁盘快照 |
| Harness | 内置 Agent、Kimi CLI、Pi、dsh 的受管适配器 | 扩大已验证的 harness 兼容范围 |
| 模型 | 本地模型与联网模型配置、能力检查、任务前选择 | 更多推理协议与自动路由 |
| 工具 | 预置 CSV 工具，通过 MCP 与 CLI 适配器调用 | 更多文件工具与执行能力 |
| 网络 | 来宾禁止直接外联；宿主网关按授权连接指定模型端点 | 更多受控服务类型 |
| 凭据 | 宿主保存模型 API Key，推理网关代持；来宾仅持任务限权凭证 | 订阅登录、更多认证方式 |
| MCP | 本地服务接入、工具发现、调用、启停及错误处理 | 远程连接器与凭据代理 |
| CLI | 隔离环境内的预装命令行工具及 Agent CLI 接入 | 扩展兼容工具与交互模式 |

Kimi CLI、Pi 和 dsh 均列入本期接入验收，具体版本和支持的模型组合必须冻结并实测。接入要求包含会话、流式输出、工具审批、停止、配置下发与错误恢复，不能以启动进程代替完成接入。至少一条 harness 与本地模型组合通过离线验收；三种外部 harness 各至少一条联网模型组合通过验收。不是每个 harness 都必须支持每个模型，不兼容组合应明确不可选。范围不足以在两天内完成时调整排期。

## 5. 实施基线

| 项目 | 约束 |
| --- | --- |
| 平台 | Apple Silicon macOS，单一测试平台 |
| 参考设备 | 16GB 及以上统一内存；最终以实测为准 |
| 分发 | 内部包，不包含签名、公证和自动升级 |
| 隔离 | 复用成熟 Linux 虚拟机运行时 |
| 推理 | 本地模型在宿主侧使用 GPU；联网模型由宿主推理网关转发 |
| 执行 | 文件处理工具、MCP server 和 CLI 子进程全部在虚拟机内 |
| 本地候选模型 | 4B～8B 量化、支持结构化工具调用，按实际兼容性选择 |
| 模型交付 | 本地模型使用校验过的离线包；联网模型保存端点、协议、模型 ID 与宿主凭据引用 |
| 并发 | 单工作空间、多会话；同一时刻仅一个活动回合或执行任务 |
| 输入 | UTF-8、逗号分隔、首行为表头的 CSV |
| 输出 | CSV、Markdown |

平台为控制周期的实施假设，尚非市场验证结论。模型依据工具调用、任务正确率、速度与内存选定，并确认许可证允许预期使用与分发。

开发前需冻结：最低系统版本、运行时与镜像版本、模型与量化版本、模型运行时版本、Agent、MCP 协议与 SDK、MCP server 及 CLI 工具版本。

## 6. 架构与边界

```text
桌面应用／可信控制层
├─ 界面与任务状态
├─ 生命周期管理
├─ 显式文件导入／导出
├─ 会话历史、Harness、模型与任务配置管理
├─ 系统凭据存储：模型 API Key，仅宿主可读
└─ 受限推理网关
   ├─ 本地模型服务：仅推理，无宿主文件或命令工具
   └─ 联网模型：按任务授权向指定端点转发，注入上游凭据
          ↑ 限定通道与任务凭证，禁止任意转发
隔离 Linux 工作空间／不可信执行层
├─ Harness 适配器：内置、Kimi CLI、Pi、dsh
├─ MCP 客户端与受控本地 MCP server
├─ CLI 适配器与受管子进程
├─ 预置文件处理工具
├─ 输入区：只读
├─ 输出区：可写
└─ 临时区：可写
```

### 6.1 模型部署

宿主侧部署便于使用 Apple Silicon 硬件加速，避免把 GPU 虚拟化作为前提。所有 harness 均通过受限推理网关调用模型；本地分支转至宿主模型，联网分支转至任务批准的服务商。执行层不可访问模型下载、管理或其他宿主服务。

### 6.2 数据边界

- 文件、任务记录和成果默认保存在工作空间。
- 推理数据可以在本机内传递至模型进程。
- 本地推理服务与宿主网关不持久记录完整提示词和文件内容；联网提供方的数据保留政策须在配置时提示，不承诺其不留存。
- 离线模式不发送云端请求；联网模式仅允许已批准的模型请求，关闭遥测与远程崩溃报告。
- 联网模型可能接收提示词、对话、被引用的文件片段和工具结果，必须在首次发送前说明；不能宣称联网任务的数据全部留在本机。
- 用户主动导出才向指定宿主位置写入成果。
- 清空工作空间不等于法证级安全擦除。

宿主操作系统、管理员及可信组件本身不在防御范围内；不承诺抵御未知虚拟机逃逸漏洞。

### 6.3 Harness、模型与工具的关系

| 对象 | 负责什么 | 不代表什么 |
| --- | --- | --- |
| Harness | 管理 Agent 循环、会话、上下文、工具调用和任务状态，例如 Kimi CLI、Pi、dsh | 不等于某个模型，也不天然意味着联网 |
| 模型提供方 | 提供推理端点与认证，部署位置为本地或联网 | 不决定 Agent 能访问哪些文件和工具 |
| 模型 | 指定提供方下的实际模型 ID、能力及上下文限制 | 相同 API 格式不保证相同工具调用效果 |
| MCP 与 CLI 工具 | 提供具体读写和计算能力 | 不是 harness，也不是推理模型 |
| 任务配置 | 绑定 harness、模型、工具权限、网络模式及数据授权 | 不能绕过工作空间的隔离策略 |

Kimi CLI 是执行器，Kimi 模型是提供方下的推理能力，两者分别配置。Pi 或 dsh 可在组合通过验证后调用 Kimi 模型；Kimi CLI 也可使用其协议支持且经过验证的其他模型。产品不把品牌名当作模型路由规则。

### 6.4 本地与联网模式

| 项目 | 本地离线 | 联网推理 |
| --- | --- | --- |
| 模型部署 | 宿主受管本地运行时 | 用户批准的远程提供方或网关 |
| 前置资源 | 本地模型包与运行时可用 | 联网端点、模型配置与 API 凭据可用 |
| 本地模型依赖 | 需要 | 不需要本地模型，本地模型不承担默认中转、审核或兜底 |
| 数据去向 | 本机模型进程与隔离空间 | 批准范围内的上下文可发给指定提供方 |
| 外联 | 禁止 | 仅宿主推理网关可访问批准模型端点 |
| 失败 | 提示错误，保留结果 | 明确网络、认证、额度或协议错误，保留结果 |
| 自动切换 | 不切换联网模型 | 不切换本地模型或其他提供方 |

一个任务使用一个明确的推理路由。本期不做自动混合路由、模型投票或本地先判断再上云。harness 若需要多个模型或子 Agent，所有模型调用必须可被约束到该路由，否则该组合不可启用。用户显式切换时结束当前任务，创建新会话；历史对话和工具结果不会默认转发给新提供方。

### 6.5 配置对象与保存位置

下列字段为 Havenbox 产品配置要求，不是外部 harness 的通用配置格式。客户端通过表单管理，适配器负责转换成对应版本的配置文件及启动参数。

| 配置对象 | 必填内容 | 保存与可见范围 |
| --- | --- | --- |
| Harness 规格 | 标识、产品名称、固定版本、适配器、会话协议、支持的模型协议与工具接入方式 | 宿主受管配置；隔离环境中安装已校验的程序 |
| 模型提供方 | 标识、显示名、部署位置、API 协议、Base URL、凭据引用 | 宿主配置；真实凭据保存在系统安全存储 |
| 模型规格 | 提供方标识、精确模型 ID、上下文与输出上限、工具调用及结构化输出能力 | 宿主配置；能力以实际检查记录为准 |
| 本地模型资源 | 文件、校验和、量化版本、运行时版本、加载参数、受管端点 | 本机资源目录；不复制到每个 harness |
| 执行配置 | harness、模型、推理参数、MCP 与 CLI 权限、网络模式、超时和用量上限 | 工作空间配置，可保存为可复用方案 |
| 任务快照 | 上述配置版本、输入引用、数据发送范围、授权记录 | 任务记录；不保存密钥或未经批准的完整敏感上下文 |

联网模型表单提供服务商模板和自定义 API 两种入口。必须填写真实模型 ID，协议单独选择；Base URL 不推断协议。模型列表能拉取时由用户选择，否则允许手填并测试。支持哪些协议由适配器矩阵决定，协议名称相同仍需验证流式输出、工具调用、错误及上下文限制。

本地模型表单选择离线包、运行时与模型 ID，展示占用、校验和、加载状态和能力检查。已有本地运行时只有在受管接入检查通过后才可选择，不能将任意宿主地址直接暴露给来宾。

示例执行方案如下，仅用于解释配置关系，不表示这些组合已经实测：

| 执行方案 | Harness | 模型提供方与模型 | 模式 | 凭据 |
| --- | --- | --- | --- | --- |
| 本地资料处理 | Pi | 本地运行时中的已验证模型 ID | 离线 | 无上游 API Key |
| Kimi 辅助处理 | Kimi CLI | Kimi API 提供方下的已验证模型 ID | 联网 | 宿主凭据引用 |
| Pi 使用 Kimi | Pi | 同一 Kimi API 提供方，协议由兼容检查确定 | 联网 | 复用宿主凭据引用 |
| DeepSeek 辅助处理 | dsh | DeepSeek API 提供方下的已验证模型 ID | 联网 | 宿主凭据引用 |

模型参数表单至少包含上下文上限、最大输出、推理强度和温度，只显示该模型与协议支持的项；不支持的参数不能静默传递。有效值取用户配置与模型、运行时、工作空间限制中的较严约束。联网方案配置请求次数、输入输出量和任务超时上限；费用估算只有在价格来源和用量可用时展示，否则显示未知，不伪造金额。

以下是执行方案的数据示意，字段属于 Havenbox，示例中的模型引用必须由实际保存并检查过的配置替换：

```json
{
  "id": "pi-kimi-online",
  "harnessRef": "pi-pinned",
  "modelRef": "kimi-api/verified-model",
  "networkMode": "online-inference",
  "toolPolicyRef": "csv-workspace-only",
  "dataPolicyRef": "task-and-approved-csv-results",
  "fallback": "none"
}
```

此方案中的模型引用指向提供方、真实模型 ID 与宿主凭据引用；导出的方案不携带 Key，也不包含可直接绕过网关的认证信息。

同一提供方的模型配置可复用于多个兼容 harness，不要求用户为每个 harness 重填密钥。工作空间默认方案用于新任务，任务内选择优先于默认值。启动时以任务快照生成有效配置，禁止外部 harness 的全局配置、缓存模型选择或隐式环境变量覆盖任务路由。

### 6.6 网关与凭据

API Key 在桌面端输入后直接交宿主凭据存储，模型配置只保留引用。隔离环境收到的是受限网关地址、模型映射及任务限权凭证，不接收上游 Key。适配器需要写配置文件时，只写上述代理信息；默认关闭会话上传、模型目录自动刷新、远程遥测和运行期更新。

宿主网关依据任务快照决定实际上游、API 协议及模型，校验路由、上下文大小、用量与期限后注入真实 Key。拒绝客户端任意覆盖 Base URL、模型或认证头。自定义端点按域名和目标地址限制，禁止转发到宿主其他服务；不将宿主网关实现为任意 HTTP 代理。

配置检查也可能联网，按钮需明确标注目标与发送内容，使用固定无文件的测试提示。已发送数据无法通过撤销收回；撤销应立即阻止新的请求并尽力取消在途请求，界面说明可能已有发送或计费。流式请求中断后不自动重发，只有确认无副作用且符合已定义策略的操作允许有限重试。

数据授权必须能落实到输入与工具返回：在上下文进入 harness 前限制允许的文件和片段，工具结果进入会话前检查发送范围，超限或追加敏感内容时暂停请求。联网网关鉴权本身不能证明模型只收到了批准字段；验收须观察实际请求内容。无法控制上下文来源或存在隐藏模型请求的组合不能启用联网模式。

本期先支持 API Key 连接。harness 的托管登录或订阅 OAuth 如果需要将真实会话凭据保存在来宾内，不得作为绕过代理的方案；界面说明当前不支持并提供 API 连接配置入口。

### 6.7 会话、回合与执行任务

会话是用户围绕同一工作持续对话的容器，包含多轮消息、文件引用、任务计划与成果。每次发送消息形成一个回合；回合可仅回答或澄清，也可提出需要确认的执行计划。确认后的文件与工具操作形成执行任务，完成、失败或停止一个任务不关闭会话，用户可以继续追问或提出下一项操作。

| 对象 | 记录内容 | 生命周期 |
| --- | --- | --- |
| 会话 | ID、标题、时间、状态、harness 与适配器版本、默认模型和权限引用 | 创建后持久保存，可重命名、归档与删除 |
| 消息与回合 | 用户输入、助手回复、必要工具摘要、发送状态、回合 ID | 按会话顺序追加，中断消息显示未完成 |
| 执行任务 | 计划、配置快照、审批、调用记录、文件版本与成果引用 | 仍沿用待确认、执行、完成、失败、停止与中断状态 |
| Harness 会话映射 | Havenbox 会话 ID、原生会话 ID、存储版本与恢复检查点 | 用于重启恢复，与进程 PID 分离 |

一个工作空间可有多个会话，但本期同一时刻只允许一个回合或任务占用模型和执行资源。其他会话可浏览历史、编辑草稿或新建空会话，发送入口暂不可用；不提供后台任务队列或并行执行。切换可见会话不会取消已有运行，也不会把其状态隐藏在另一个会话的消息里，界面始终显示活动任务及返回入口。

会话默认绑定同一 harness、模型与网络模式，可在多轮中连续使用。执行任务仍各自持有不可变配置快照。切换 harness、模型或模式创建新会话，用户可选择带入一份可预览的历史摘要和文件引用；不承诺跨 harness 恢复其内部状态，也不默认复制完整对话。旧会话保留可查看，联网提供方变化时重新授权携带内容。

多轮上下文取自当前会话允许的消息、文件引用及工具结果，不包含其他会话历史。会话文件默认仅向本会话开放；复用其他会话成果时用户显式选择，生成可追溯的文件引用并重新检查权限。删除会话先清理其独有附件和原生历史，仍被其他会话引用的成果不得连带删除，宿主原件和已导出文件不受影响。

会话消息和原生 harness 历史保存在本机工作空间的受管持久目录，不同步至云端。此处允许保存用户可见对话与恢复所需的批准上下文，不等于推理网关持久记录完整请求，也不要求存储模型内部推理内容。来宾会话文件不能含真实上游凭据；敏感工具输出默认保存摘要和文件引用，完整内容仅在用户可见且符合数据策略时保存。

恢复分为“浏览历史”和“继续对话”。重启时先恢复消息与成果索引，再校验 harness 版本、原生会话、文件引用、模型连接与权限。原生恢复通过验证时使用其会话 ID 继续；否则明确提示“以历史摘要新建会话”，用户确认后按批准上下文重建，不伪装原生恢复。损坏的原生记录不应阻止查看仍完好的 Havenbox 历史。

崩溃、停止或断网后的未完成回合标为中断。恢复不得自动重放工具操作或重发联网请求；结果不确定时先检查调用记录与已有成果。用户选择继续后产生新的回合和必要计划确认。保存消息与事件使用稳定 ID 和顺序，恢复或重新连接不能重复展示消息或执行同一调用。

上下文超限时展示摘要与被省略范围，保留可浏览的原始历史，不静默截断关键指令或工具约束。发送给联网模型的历史摘要也属于授权范围，继续会话前重新核验当前任务凭证和授权，不能用过期审批延续执行权限。

## 7. 用户流程与界面

### 7.1 首次启动

检查隔离运行时 → 选择“本地离线”或“联网模型” → 配置并检查模型 → 选择兼容 harness 与工具权限 → 工作空间就绪。选择联网模型时无需安装或加载本地模型。

资源缺失时说明原因，不自动下载或切换云端。资源包可在联网准备阶段取得，运行期离线与安装期联网必须明确区分。

### 7.2 执行任务

选择 harness、模型及权限配置 → 导入 CSV → 校验并展示字段摘要 → 输入任务 → 本地路径直接生成计划，联网路径先确认将发送的数据 → 生成计划 → 澄清歧义 → 用户确认执行 → 预览与导出。

计划示例：“合并 3 个文件，按门店汇总销售额，将金额小于零的记录另存。原文件保持不变。”

### 7.3 主界面

| 区域 | 内容 |
| --- | --- |
| 任务区 | 指令、计划确认、进度、结果摘要 |
| 文件区 | 输入、输出、预览、导出 |
| 状态区 | 当前 harness、模型、离线或联网标识、环境状态、停止 |
| 接入管理 | Harness、MCP、CLI 工具与权限 |
| 模型与连接 | 本地资源、联网提供方、模型列表、凭据管理与连接测试 |
| 设置 | 资源状态、版本、诊断、重启、重置 |

普通任务流程不要求用户管理虚拟机桌面、终端、端口或挂载配置。CLI 在后台运行，界面展示所选工具、调用范围、状态及脱敏日志。

### 7.4 Harness 与模型的配置动线

1. 打开“模型与连接”，选择本地或联网。本地校验资源并加载；联网选择提供方模板或自定义 API，填写协议、Base URL、API Key 与模型 ID。
2. 点击检查。先告知测试是否联网及目标，通过认证、协议与最小工具调用检查后保存。区分“已保存”“连接可用”“能力已验证”，不能仅靠模型列表请求成功就显示任务可用。
3. 打开“接入管理 → Harness”，选择 Kimi CLI、Pi 或 dsh，检查固定版本与适配器，绑定刚保存的模型和已批准工具。
4. 检查组合能力。展示流式输出、工具调用、MCP 桥接、停止与会话恢复的支持情况及失败原因，兼容后保存执行方案。
5. 工作台选择执行方案，持续显示 harness、提供方、模型及模式。联网任务在第一次生成计划之前确认数据发送范围；执行计划确认再展示具体工具和文件操作。
6. 任务运行时冻结选择。修改模型、端点、权限或模式会使旧计划失效，新任务重新授权；删除提供方或撤销凭据前说明受影响任务并提供停止动作。

联网数据授权与工具执行确认是两次不同的决定。默认只发送任务文字、必要字段与有限工具结果；提供方可见范围须覆盖后续会话追加内容，超出范围时暂停并再次授权。文件在本机不代表其内容未进入联网提示词。

### 7.5 会话动线

新建会话 → 选择执行方案 → 发送消息 → 澄清或生成计划 → 确认并执行 → 查看结果 → 在同一会话继续追问。只读问答不要求每轮确认文件执行计划，但仍遵守联网数据授权和单活动回合限制。

侧栏展示会话标题、最近消息时间与状态，支持新建、搜索标题、重命名、归档与删除。点击历史会话可浏览，继续发送前检查模型、文件及权限。删除进行中的会话必须先停止并确认清理，不能通过删除界面条目遗留后台进程。

## 9. 工具与可靠性

### 9.1 最小工具集

| 接口 | 职责 |
| --- | --- |
| inspect_csv | 字段、类型候选、样例和行数 |
| concat_csv | 匹配字段纵向合并 |
| filter_rows | 按受支持条件筛选 |
| aggregate_csv | 分组、计数、求和 |
| write_report | 根据工具返回事实写报告 |

工具接收工作空间文件标识，不接受任意宿主路径。初版条件使用声明式参数，不执行用户或模型提供的表达式代码。

### 9.2 处理规则

- 计算由确定性程序完成，金额使用十进制定点方式。
- 非法数值不得静默按零处理。
- 字段不匹配、缺少指定列时暂停，不自行丢弃字段。
- 输出包含输入、输出及解析失败或排除行数。
- 报告数字以工具结果为依据。
- 文件内容仅作为数据，不授予额外权限。
- 执行完成不等于业务结论正确，保留检查入口。

### 9.3 MCP 接入

本期由工作空间内的 MCP 客户端连接预装的本地 MCP server，使用 stdio 传输。实现初始化、工具发现、参数校验、工具调用、错误返回和进程清理。首个服务提供预置 CSV 工具，涉及输出写入的工具沿用计划确认和文件权限策略。

接入配置包含服务标识、可执行文件、参数、允许的环境变量和工具权限。配置经程序校验后生效。服务提供的工具描述只用于发现，不能修改权限策略。远程 MCP、动态安装服务和业务账号认证不属于本期范围。

### 9.4 CLI 接入

CLI 指工作空间内的命令行工具与 Agent CLI 接入、调用和生命周期管理。本期不另行承诺一套宿主侧 `havenbox` 管理命令。

适配器配置明确的可执行文件、参数 schema、工作目录、环境变量白名单和资源上限。参数以列表传入，不接受模型生成的 shell 字符串。普通工具返回结构化结果或可解析输出，确定性 CLI 模板不需要模型。Agent CLI 连接受限推理网关并使用任务指定模型，均不能获取宿主文件和命令权限。

Agent 的调用范围在执行前纳入计划确认。适配器捕获标准输出、标准错误及退出码，限制日志大小并脱敏。超时、用户停止或应用退出时终止进程树。协议、工具能力或模型不兼容时明确失败，不自动更换 harness、模型或网络模式。

### 9.5 三种 harness 的接入方式

以下官方接口核查日期为 2026-10-23。它们证明存在可用的集成方向，不代表 Havenbox 已完成适配或安全测试。外部配置路径均位于隔离环境的独立受管目录，不读写用户宿主上的同名目录。

| Harness | 产品接入方式 | 模型配置映射 | 工具与会话处理 |
| --- | --- | --- | --- |
| Kimi CLI | 预装固定版本，以 `kimi acp` 子进程的 ACP 接口管理会话和事件 | 将提供方、模型与代理认证映射到受管 `config.toml`，使用独立 `KIMI_CODE_HOME` | 通过受管 MCP 配置或 ACP 会话传入工具，接管审批与取消，并核对内置工具权限 |
| Pi | 预装固定版本，以 `pi --mode rpc` 接入 JSONL 命令、响应及事件 | 将端点、协议和模型映射到独立 agent 目录的 `models.json`，会话显式指定模型 | 将已批准 MCP 工具通过受审扩展或桥接注册，不假设原生 MCP 支持；映射工具事件、停止与会话状态 |
| dsh | 使用固定版本 `sdk` profile 的 JSON-RPC 服务，通过适配器管理会话；不用网页抓取代替协议 | 在独立 `DSH_HOME` 的 profile 配置中映射提供方和模型，代理认证代替上游凭据 | 配置受管插件组合，验证工具权限、MCP 插件或桥接、事件与终止；不得直接放开默认整套插件 |

接入依据：[Kimi ACP](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-acp)、[Kimi 配置](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)、[Kimi 提供方](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/providers)、[Pi RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)、[Pi 模型](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)、[dsh 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[dsh 模型](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)。

适配器统一对外提供能力检查、创建会话、提交任务、接收事件、处理审批、停止与关闭。ACP、Pi RPC 和 dsh JSON-RPC 不是同一协议，字段、事件和恢复机制分别转换。不能解析终端展示文字作为唯一控制协议。

每个 harness 固定版本后记录模型协议、工具能力及安全配置。内置 shell、文件工具、子 Agent、插件和 MCP 均受沙箱边界限制；若无法控制外联、工具范围或清理子进程，则组合不能启用。dsh 的 SDK profile、Pi 扩展及 Kimi 审批映射须通过实际样例验证，不能只凭文档声明支持。

## 10. 安全需求

| 编号 | 强制要求 |
| --- | --- |
| S01 | 不共享主目录、SSH agent、Docker socket、剪贴板和管理接口 |
| S02 | 来宾禁止直接访问互联网、局域网和宿主其他服务；联网模型流量只由宿主网关按批准端点转发 |
| S03 | 仅允许访问受限推理网关及明确的控制通道，不能访问宿主其他服务 |
| S04 | 推理入口限制接口、模型、请求大小、并发与超时 |
| S05 | 不允许任意地址转发、模型下载、管理或宿主命令执行 |
| S06 | 输入区只读，宿主原文件不直接交给执行层 |
| S07 | 所有文件接口验证路径、符号链接和类型 |
| S08 | 预览不执行脚本、不加载远程内容，单元格按纯数据呈现 |
| S09 | 本地模型、harness 与工具预装，不在任务中下载依赖；联网模型仅访问推理接口 |
| S10 | 关闭遥测与远程日志，诊断不收集完整文件 |
| S11 | 限制虚拟机资源、磁盘与推理上下文 |
| S12 | 模型失败时提示，不自动回退云端 |
| S13 | MCP 配置仅允许预装的本地服务，工具发现结果不自动授予权限；调用时校验工具、参数及文件权限 |
| S14 | CLI 通过明确的可执行文件和参数列表启动，不经 shell 拼接；拒绝未授权命令、参数及环境变量 |
| S15 | MCP 与 CLI 使用独立受限环境，不继承宿主凭据、代理变量或管理端点；取消和退出清理进程树 |
| S16 | 联网模型真实凭据仅在宿主网关注入；来宾凭证绑定任务、提供方、模型、期限与用量限制，可撤销 |
| S17 | 自定义模型端点须校验协议、域名、端口和目标地址，拒绝私网、环回、元数据端点及越权重定向；本地推理走独立受管路由 |
| S18 | 所有模型调用含规划、总结和子 Agent 均受任务路由约束；禁止隐式外联、自动换模型及自动跨提供方重试 |
| S19 | 会话历史和恢复文件留在本机，不含上游凭据；恢复重新校验文件、模型和权限，旧审批不能重放或跨会话使用 |

CSV 导出需检测公式注入风险并提示。若提供转义版本，应明确其与原样数据的区别，不能静默修改数据。

## 11. 状态与异常

工作空间：未初始化 → 初始化中 → 就绪 → 运行中；另有模型不可用、环境异常、资源不足、重置中。

任务：待理解 → 待确认 → 执行中 → 已完成／失败／已停止／已中断。

会话：空会话、可继续、处理中、待恢复、只读、已归档。消息另有草稿、发送中、已完成、失败和中断状态。归档会话默认只读，取消归档后重新检查再继续；记录或版本不兼容时仍可浏览，但需按第 6.7 节新建会话恢复上下文。删除为有确认的持久操作，不等同于归档。

| 异常 | 行为 |
| --- | --- |
| 模型包缺失或损坏 | 阻止依赖该本地模型的任务，提示导入资源；已配置联网方案不受其影响 |
| 内存不足 | 提示关闭应用或选择其他已验证方案，不无限重试或自动上云 |
| 工具格式错误 | 有限次数修正，超限失败 |
| 不支持任务 | 说明范围，不尝试任意代码 |
| 业务规则有歧义 | 澄清，不猜测关键规则 |
| 执行超时 | 终止并保留可检查结果，标明未完成 |
| 停止失败 | 提供关闭工作空间的兜底操作 |
| 崩溃退出 | 核查清理遗留进程，标记中断，不自动续跑 |
| MCP 启动或调用失败 | 展示服务与调用错误，执行有限重试，禁止自动切换到未授权工具 |
| CLI 异常退出或输出超限 | 保留脱敏诊断与退出码，终止关联任务，不把部分输出标为成功 |
| 联网认证、额度或网络故障 | 区分原因，暂停并保留结果；不自动换提供方或本地模型 |
| Harness 与模型不兼容 | 禁用组合并说明协议或能力缺口，保留其他有效配置 |
| 凭据撤销或网络模式变更 | 阻止新请求，停止受影响任务，重新配置后创建新会话 |

## 13. 验收标准

### 13.1 功能与准确性

- 固定样例覆盖合并、筛选、汇总及错误输入。
- 结果与预期一致，无静默丢行。
- 原文件不变，输出可预览导出。
- 重启后文件保留，停止后任务不继续。
- 故障与中断不会显示成功。
- 至少一个预装本地 MCP server 完成配置、发现、真实工具调用、禁用和故障处理。
- 至少一种命令行工具在隔离环境内完成真实任务，输出和退出码可检查。三种 harness 按第 13.4 节分别验收。
- 相同 CSV 样例经 MCP 与 CLI 入口处理，结果与预期一致；两种入口均支持停止和超时清理。

### 13.2 离线与隔离

- 本地方案所需资源已安装后，物理断网可启动、执行、重启和导出；联网方案断网时明确不可用。
- 网络观测确认无非预期外联；断网可用本身不足以证明没有外联尝试。
- 来宾不能读取宿主测试文件或访问互联网、宿主其他服务和局域网。
- 路径穿越、符号链接和特殊文件无法绕过文件接口。
- 推理入口不能访问模型管理或宿主执行能力。
- 重置不删除宿主原件或模型包。
- MCP 与 CLI 路径穿越、命令注入、未授权工具及环境变量注入测试被拒绝。
- 已验证的本地 harness 组合与本地 MCP server 在断网下可工作，无非预期外联；所有组合在停止、重置及崩溃恢复后无遗留任务进程。

### 13.3 用户验证

至少 3 位非技术用户完成真实 CSV 任务，无需终端或理解虚拟机；能理解处理范围，完成确认、停止、预览、导出，能区分执行用的 harness、推理模型与工具，并知道本次任务是否向服务商发送数据。

### 13.4 Harness 与模型配置验收

- Kimi CLI、Pi、dsh 各用固定版本完成一条联网模型真实任务，验证会话、流式事件、工具调用、审批、停止、失败显示和进程清理。
- 至少一条 harness 与本地模型组合在物理断网后完成相同 CSV 任务；联网模型未配置时不影响该路径。
- 不安装本地模型，仅配置已验证的联网组合，也能完成配置、计划、执行与导出。
- 同一联网模型在至少两种支持该协议的 harness 中复用提供方配置并完成任务，不重复暴露密钥。
- 联网数据首次发送之前已有有效授权，观测实际出口、模型与发送字段符合任务快照。拒绝授权时无业务推理请求。
- 从来宾文件、进程环境和日志读取不到上游 Key；限权凭证不能访问其他提供方、模型、管理接口或任务。
- 修改 harness 原生配置、环境变量及会话缓存不能绕过已批准路由。所有子 Agent 请求也必须经过同一网关策略。
- 本地失败、联网失败或不兼容时不自动跨模式切换；切换模型或提供方创建新会话，不默认转发旧对话。
- 配置导出不含密钥；替换与撤销凭据阻断后续请求；运行中不能静默修改任务快照。
- 兼容矩阵按 harness 版本、适配器版本、协议、模型 ID、工具方式和验收结果记录，未验证组合显示不可用及原因。

### 13.5 会话验收

- 同一会话完成“汇总 CSV → 解释结果 → 修改条件重新汇总”，前一成果保留，后一次操作有独立计划与调用记录。
- 新建两条会话，消息、文件权限与模型上下文不串用；一条处理中时另一条可浏览和编辑草稿，但不能并发发送。
- 正常退出重启后，消息、任务状态和成果引用仍可查看；三种 harness 分别验证原生继续或明确的历史重建路径，并展示实际采用的策略。
- 模拟流式中断、工具结果未知与应用崩溃，恢复后不自动重发请求、重复执行工具或将半条回复标为完成。
- 文件缺失、harness 升级或模型不可用时，历史仍能打开，并明确继续对话的前置条件。
- 上下文超限的摘要可查看，原始历史仍可浏览；带入新会话或联网模型的内容在发送前已有有效授权。
- 搜索、重命名与归档状态重启后保留；删除需确认并清理独有历史，保留跨会话引用成果、宿主原件和导出文件。
