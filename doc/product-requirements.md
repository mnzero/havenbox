# 桌面级 Agent 安全工作空间 MVP PRD

版本：V0.6

更新日期：2026-10-25

状态：MVP 实施基线

交付目标：在 Apple Silicon macOS 上交付一条可供内部用户完成真实 CSV 任务的安全执行链路。

关联文档：[技术方案](./technical-design.md)、[执行计划](./development-tasks.md)、[UI 设计](./ui-ux-design.md)、[MVP 复审记录](./technical-review.md)

## 1. 产品定义

Havenbox 是桌面 Agent 安全工作空间。用户导入 CSV、描述任务、确认模型可见的数据和执行计划，然后在隔离环境中运行确定性工具。用户检查结果后主动导出。

MVP 验证一个产品假设：非技术用户不管理虚拟机，也能限制 Agent 对宿主文件、凭据、命令和网络的访问。

MVP 不验证多 harness 兼容、本地离线推理或通用工具生态。这些能力在核心链路通过后再实现。

## 2. 产品原则

优先级如下：

1. 隔离边界成立。
2. 任务结果准确且可检查。
3. 用户能完成完整流程。
4. 扩展模型、harness 和工具。

以下规则不因 MVP 缩小而放宽：

- 不可信执行只在虚拟机中运行。
- 文件只通过显式导入和导出跨越边界。
- 模型负责理解意图。确定性程序负责计算和文件写入。
- 用户在首次联网请求前批准发送范围。
- 用户批准执行计划后，程序才签发工具调用许可。
- 失败、停止和结果未知不能显示为成功。

## 3. 用户与场景

### 3.1 目标用户

目标用户是需要处理本地资料、重视数据边界、但不熟悉虚拟机和 Agent 配置的内部试用者。测试设备为 Apple Silicon Mac，统一内存不少于 16 GiB。

### 3.2 MVP 场景

用户导入一份或多份 UTF-8 CSV，并提出以下一种或多种要求：

- 查看字段和样例。
- 合并字段一致的文件。
- 按声明式条件筛选记录。
- 按字段分组、计数或求和。
- 按明确规则查找异常，例如负数或重复订单号。
- 生成 CSV 和 Markdown 报告。

用户完成数据披露确认和计划确认后，Havenbox 在虚拟机中执行任务。原文件保持不变。用户预览结果后选择导出位置。

### 3.3 非目标

MVP 不包括以下能力：

- Kimi CLI、Pi、DeepSeek Harness 或其他外部 harness。
- 本地模型和物理断网推理。
- MCP。
- 自定义模型端点、多提供方切换和兼容矩阵管理。
- 多会话、搜索、归档、跨会话引用和原生会话恢复。
- 浏览器自动化、任意代码、任意 shell 和动态安装依赖。
- Excel、PDF、OCR、业务账号和远程连接器。
- 签名、公证、自动更新和公开分发。

## 4. MVP 范围

| 能力 | MVP | 后续版本 |
| --- | --- | --- |
| 工作空间 | 一个持久化工作空间，一个活动任务 | 多工作空间和多会话 |
| Agent | Havenbox 内置 Agent | Kimi CLI、Pi、dsh |
| 模型 | 一个固定的联网提供方、协议和模型 | 本地模型、多提供方、自定义端点 |
| 工具 | 预装 CSV 引擎，通过固定 CLI 适配器调用 | MCP 和更多文件工具 |
| 网络 | 来宾无网卡；宿主网关只访问冻结的模型端点 | 更多受控服务 |
| 凭据 | API Key 保存在宿主 Keychain | OAuth 和更多认证方式 |
| 历史 | 保存任务、审批、调用和成果；重启后只读查看 | 继续对话和原生恢复 |
| 分发 | 固定内部包 | 签名、公证和升级 |

MVP 只发布一个已通过功能和安全验收的组合。配置页不允许用户添加任意端点或未验证模型。

## 5. 实施基线

| 项目 | 约束 |
| --- | --- |
| 平台 | Apple Silicon macOS，单一参考设备 |
| 分发 | 内部包 |
| 隔离 | 固定 Linux 虚拟机运行时，无虚拟网卡和宿主目录共享 |
| 推理 | 宿主网关转发到一个冻结的联网模型 |
| 执行 | CSV 引擎和 CLI 在虚拟机内运行 |
| 并发 | 同一时刻只有一个活动任务 |
| 输入 | UTF-8、逗号分隔、首行为表头的普通文件 |
| 输出 | CSV 和 Markdown |
| 资源 | 文件、磁盘、内存、步骤、输出和超时均有固定上限 |

产品基线必须记录运行时、镜像、模型、协议、工具、构建工具链、资源上限和制品摘要。任务运行时不下载或更新依赖。

## 6. 架构与边界

```text
桌面应用和可信宿主层
├─ 配置、Keychain 和任务状态
├─ 文件导入、预览和导出
├─ 数据披露与计划审批
├─ 内置 Agent
└─ 受限推理网关
          ↑ 固定协议、端点、模型和任务凭证
隔离 Linux 虚拟机
├─ Supervisor
├─ 固定 CLI 适配器和 CallPermit 校验
├─ 确定性 CSV 引擎
├─ 只读输入区
├─ 可写输出区
└─ 可写临时区
```

宿主控制生命周期、审批、凭据、模型请求和文件跨界。来宾只处理本次任务已批准的文件和命令。模型不能读取宿主文件、调用宿主命令或改变工具权限。

### 6.1 联网推理

MVP 使用一个冻结的联网模型组合。宿主网关从任务快照选择端点、协议和模型，并注入 API Key。来宾不能覆盖 URL、模型、认证头或代理设置。

首次业务请求前，界面显示提供方、模型和发送内容。用户拒绝后，网关不得发送业务请求。流式请求中断后不自动重发，也不切换模型。

### 6.2 文件边界

宿主复制用户选择的普通 CSV，并保存不可变输入版本。程序拒绝目录、符号链接、特殊文件、路径穿越、并发替换和超限文件。

来宾输入区只读。工具只写输出区和临时区。宿主校验成果哈希、类型和来源后才显示成果。导出使用宿主保存面板，覆盖现有文件前必须确认。

### 6.3 任务与历史

一个工作空间只有一个活动任务。任务保存配置快照、披露决定、计划、调用、成果和终态。

重启后，用户可以查看已保存的任务和成果。未完成任务标记为中断。MVP 不自动重放模型请求、工具调用或继续对话。

## 7. 用户流程与界面

首次启动流程如下：

1. Havenbox 检查虚拟机、镜像、模型配置和 Keychain 凭据。
2. 用户输入 API Key，并运行固定的无文件连接检查。
3. Havenbox 只在检查成功后启用任务入口。

任务流程如下：

1. 用户导入 CSV。
2. 用户输入任务要求。
3. Havenbox 展示拟发送给模型的数据。
4. 用户批准或拒绝数据披露。
5. 内置 Agent 生成声明式计划。规则不明确时，Agent 要求用户补充。
6. Havenbox 展示输入、操作和预期输出。
7. 用户批准计划。
8. 虚拟机执行确定性工具。
9. 用户预览 CSV 和 Markdown 成果。
10. 用户选择成果和宿主目标位置后导出。

运行中，界面始终显示活动阶段和停止按钮。停止完成前，用户不能开始新任务。

## 8. 功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F01 | 自动准备 | 资源齐备时，用户无需终端即可进入任务页 |
| F02 | 文件导入 | 只接受符合限制的普通 CSV，并保存不可变输入版本 |
| F03 | 任务理解 | 内置 Agent 生成符合 schema 的参数，关键规则不明时要求补充 |
| F04 | 数据披露 | 首次业务请求前展示并保存发送范围；拒绝时业务请求为零 |
| F05 | 计划审批 | 展示输入、操作和输出；批准的计划改变后必须重新审批 |
| F06 | 确定性执行 | CLI 只执行固定 CSV 命令，并校验许可、参数和成果 |
| F07 | 停止与退出 | 取消模型请求和来宾进程；清理确认前保持忙碌 |
| F08 | 预览与导出 | 安全预览 CSV 和 Markdown；覆盖宿主文件前确认 |
| F09 | 持久化 | 重启后可以查看任务、审批、调用和成果 |
| F10 | 重置 | 二次确认后删除工作数据，不删除宿主原件和已导出文件 |
| F11 | 诊断 | 保存脱敏状态、版本、错误码和调用计数，不保存 Key 或完整 CSV |
| F12 | 明确失败 | 认证、网络、格式、资源、工具和清理失败均有可诊断状态 |

## 9. 工具与可靠性

MVP 预装以下工具：

| 工具 | 职责 |
| --- | --- |
| `inspect_csv` | 返回字段、类型候选、样例和行数 |
| `concat_csv` | 纵向合并字段一致的 CSV |
| `filter_rows` | 按声明式条件筛选记录 |
| `aggregate_csv` | 分组、计数和求和 |
| `write_report` | 根据工具事实生成 Markdown 报告 |

工具接收工作空间 `FileId`，不接受宿主路径。金额使用十进制定点计算。非法数值、缺少字段和精度溢出必须失败。程序不能把非法值改为零，也不能静默丢行。

CLI 使用固定 executable 和参数 schema。程序以参数数组启动进程，不使用 shell 字符串。`CallPermit` 绑定任务、计划、工具、参数、输入、输出、期限和资源限制。成果只有在内容、哈希、类型和来源均通过校验后才能发布。

## 10. 安全需求

| 编号 | 强制要求 |
| --- | --- |
| S01 | 来宾没有虚拟网卡、宿主目录共享、SSH agent、Docker socket、剪贴板或管理接口 |
| S02 | 来宾只能访问固定控制、文件和推理通道，不能访问互联网、局域网或宿主其他服务 |
| S03 | 输入区只读；输出区和临时区有文件类型、路径和容量限制 |
| S04 | 所有文件接口拒绝路径穿越、符号链接、特殊文件和并发替换 |
| S05 | 工具只接受固定 executable、参数列表、工作目录和环境变量 |
| S06 | 未批准、已使用、过期、撤销或绑定不匹配的调用许可必须失败 |
| S07 | 停止、退出、超时和失联必须清理来宾与宿主受管进程 |
| S08 | API Key 只保存在宿主 Keychain，并且不进入来宾、数据库、日志或导出配置 |
| S09 | 网关只允许冻结的协议、端点和模型，并限制请求大小、次数、并发和超时 |
| S10 | 任务不自动下载依赖、重试写操作、切换模型或回退到其他模式 |
| S11 | 预览不执行脚本、终端控制序列或远程内容；CSV 公式风险必须提示 |
| S12 | 模型输出、文件内容和工具输出不能扩大权限或改变安全策略 |

## 11. 状态与异常

任务状态如下：

```text
准备中 -> 等待数据披露 -> 规划中 -> 等待计划确认
       -> 执行中 -> 总结中 -> 已完成
```

任何非终态都可以进入停止中、失败或中断。程序只有在进程和在途请求完成清理后才进入已停止。

常见异常按以下规则处理：

| 异常 | 行为 |
| --- | --- |
| VM、镜像或模型配置不可用 | 阻止任务并显示缺失资源 |
| CSV 不合法 | 拒绝对应文件并给出原因 |
| 业务规则不明确 | 要求用户补充，不猜测关键条件 |
| 认证、额度、TLS 或网络失败 | 保留现有结果，不重试或换模型 |
| 工具超时或异常退出 | 终止任务并保留脱敏诊断 |
| 结果无法确认 | 标记结果未知，不自动重跑 |
| 清理失败 | 保持忙碌，并提供关闭工作空间操作 |
| 应用崩溃 | 重启后标记任务中断，不自动续跑 |

## 12. 实施计划

MVP 按一条端到端链路推进。详细任务和依赖见[执行计划](./development-tasks.md)。

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| 1 | 重整基线，冻结唯一组合 | 清单、限制、样例和验收入口一致 |
| 2 | 打通无界面的真实任务 | 一个模型请求和一个真实 VM 工具任务产生可校验成果 |
| 3 | 完成文件、审批、停止和持久化 | 越权请求失败，停止无残留，重启不重放 |
| 4 | 完成桌面主流程 | 用户无需终端完成导入、确认、执行、预览和导出 |
| 5 | 完成安全验收和内部试用 | 第 13 节全部通过并生成固定内部包 |

任何阶段都不能用模拟调用替代退出条件。隔离边界失败时，团队修复运行时或停止交付，不改为宿主直接执行。

## 13. 验收标准

### 13.1 端到端任务

- 用户导入固定 CSV 样例并提出分组汇总和异常筛选要求。
- 模型生成符合 schema 的计划。
- 用户可以拒绝或批准数据披露和执行计划。
- 虚拟机中的真实 CLI 调用 CSV 引擎，并生成预期结果。
- 固定样例的金额、行数、排除数和重复键结果与期望一致。
- 原文件哈希不变，成果可以预览和导出。
- 重启后仍可查看任务和成果，但不会继续未完成任务。

### 13.2 隔离与安全

- 来宾不能读取宿主探针文件，也不能访问互联网、局域网和宿主其他服务。
- 路径穿越、符号链接、特殊文件、命令注入和环境变量注入均被拒绝。
- 未批准或篡改的模型请求与工具调用均被拒绝。
- 实际模型出口只包含已批准内容。
- 来宾文件、进程环境、日志和配置中没有上游 API Key。
- 停止、退出、超时和应用崩溃后没有任务进程继续运行。
- 写入、成果提交和导出阶段发生故障时，程序不显示伪成功。

### 13.3 用户验证

至少 3 位目标用户无需终端即可完成同一真实 CSV 任务。每位用户都能说明哪些数据发送给模型，并完成计划确认、停止、预览和导出。

### 13.4 交付判定

只有同一个冻结组合同时通过端到端验收和安全验收，内部包才启用任务入口。候选测试授权不能进入交付包。

## 14. 后续版本

MVP 通过后按证据决定下一项能力。推荐顺序如下：

1. 本地模型和物理断网路径。
2. 一个外部 harness。
3. MCP。
4. 多会话和继续对话。
5. 更多 harness、模型和工具。
6. 签名、公证、自动更新和公开分发。
