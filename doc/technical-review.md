基线：PRD V0.5、技术方案 V0.1 的工作区快照、UI V0.5.1 与仓库 AGENTS.md。

| 编号 | 缺口与影响 | 修订位置与处理 | 落地任务 |

| RV-02 | F04/F05/F06 规划需要表头，但检查字段又像是先需批准计划，形成循环 | §5.4.1，导入许可生成绑定哈希的结构元数据，联网披露单独批准 | HB-12、HB-18 |
| RV-03 | PRD §3.2 的订单号重复无法用普通逐行比较实现 | §5.6，定义 duplicate_key、复合键、空值、保留方式及稳定顺序 | HB-13、HB-14、HB-15 |

## 2. 规范与架构合理性

以下问题涉及项目要求的可验证边界、明确写入权属与可恢复数据操作。前 3 项为 P1，其余 4 项为 P2。均已修订设计，实际安全结论仍需相应任务取得证据。

| 编号 | 问题与影响 | 修订位置与处理 | 落地任务 |
| --- | --- | --- | --- |
| RV-07 | helper 死亡后笼统依赖子进程租约，QEMU/模型未必实现，会遗留后台计算 | §3.1，按需 launchd job、同进程组前台子进程、禁用 KeepAlive、系统清理；目标系统实测为门槛 | HB-03、HB-11、HB-25 |
| RV-08 | MCP client、stdio 与启动权归属不明，harness 可能绕过 CallPermit | §4.2/§5.5，supervisor 独占真实通道与 worker，harness 只接工具桥 | HB-14、HB-15、HB-21、HB-22、HB-23 |
| RV-09 | GC 查询后异步删除存在竞争，JSON 披露和终态导出也未定义引用释放 | §6.2/§6.4，关系引用、file_pins、事务占用 deleting、禁止新引用与幂等确认 | HB-10、HB-26、HB-29、HB-32 |
| RV-10 | 共享成果“来源墓碑”没有实体，删除 task 会断外键或残留独有历史 | §6.2/§6.4，独立 provenance，最小版本/规则摘要/输入哈希，不强制保留原输入字节 | HB-10、HB-26 |
| RV-11 | 批准上下文只有哈希，没有保存与重建契约；规划等待状态却写在未创建 task | §5.4/§5.4.1/§6.2/§7.1，context_items、disclosure_items、model_receipts、序列化版本与 turn continuation | HB-10、HB-18、HB-19、HB-24 |
| RV-13 | source_session_id 的外键未定义删除语义，可能阻止源删除或连带删目标引用 | §6.2，来源外键可空并 ON DELETE SET NULL，目标访问权独立保留 | HB-10、HB-26 |
| RV-14 | 首次披露先于任务创建，approvals.task_id 却未声明可空 | §6.2，披露绑定 turn，执行批准原子创建 task 并绑定计划摘要 | HB-10、HB-18、HB-19 |

本轮同时修正文档现状描述：仓库已有可点击模拟原型和原型检查，仍无真实产品实现。补充内部包 HVF entitlement 的构建约束、活动期导入与输入冻结、连接/权限动态撤销、工具 stdout 与大文件通道的分离。它们没有扩大 PRD 范围。

## 3. 仍需实证的架构门槛

| 门槛 | 未知事实 | 对应退出标准 |
| --- | --- | --- |
| 无网 VM | 选定 QEMU ARM/HVF 设备与串口桥在目标 Mac 是否稳定 | HB-02 的真实启动、持久盘、限额帧和越权探测 |
| 失联清理 | 目标系统的用户 job、helper 和受管二进制是否服从进程组清理 | HB-03 与 HB-25 的逐进程强杀，无残留或自动续跑 |
| 三种 harness | 是否可禁用旁路工具、控制隐藏上下文、保持会话和可靠取消 | HB-04 至 HB-06 的固定版本探针，HB-21 至 HB-23 的真实正式适配 |
| 精确披露 | 实际模型协议与原生历史能否匹配宿主授权材料 | HB-18 与 HB-32 的实际出口检查和未授权标记拒绝 |
| 本地资源 | 16GB 设备的真实模型效果、内存与工具调用是否可用 | HB-07 选型，HB-31/HB-33 完整本地任务与断网验收 |
| 分发条件 | entitlement、用户 job 注册、许可证与内部包安装是否满足无终端使用 | HB-08 冻结，HB-33 干净环境内部包验证 |

这些未知事实不以文档声明解决，也不要求现在删减本期能力。先锁定候选进行探针，再冻结可实现基线与排期；失败时调整方案/版本并复验。

## 4. 评审结论与验证范围

需求轴发现 7 项细节缺口；规范与架构轴发现 7 项问题。其中 3 项 P1、11 项 P2，均已在设计层修订。完整 F/S 需求已拆到任务，但实现状态全部为未开始。

本轮验证范围为需求对照、工作区修订 diff、文档引用、任务依赖无环与需求编号覆盖。没有执行真实 VM、模型、harness、MCP、CLI、网络或进程清理测试，不能据此宣称产品能力与安全边界通过。
