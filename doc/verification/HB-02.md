# HB-02 VM 建设与验证证据

日期：2026-10-24
工作区：`feat-hb-01-lock`。本次验证起点为 `cc5a2e9`。依据：origin/main `AGENTS.md`、PRD S01/S02/S03/S07/S11、`doc/development-tasks.md` HB-02。

## 结果

**passed：真实 VM smoke 验收通过。** 本次使用 UTM 5.0.8 中的 ARM64 QEMU 10.0.12 framework 和 HVF 启动真实 Linux guest。Guest 将 ext4 `/dev/vda` 只读挂载为 `/`，将独立的 `/dev/vdb` 作为可写持久盘。第一次启动写入持久标记，停止 VM 后第二次启动读到同一标记。两次启动均通过随机 nonce 串口握手。

本结论不依赖 `run.sh self-test` 或 fake QEMU 测试。它来自下文记录的两次真实 QEMU 启动。

## 验证方法

### 构建并校验资产

本次把 UTM 只读挂载到 `/Volumes/UTM/UTM.app`。`build-smoke-guest.sh` 要求 `mke2fs`，本次使用原生 ARM64 Homebrew `e2fsprogs` 1.47.4。

```sh
export PATH=/opt/homebrew/opt/e2fsprogs/sbin:$PATH

experiments/vm/build-utm-launchers.sh /Volumes/UTM/UTM.app
experiments/vm/build-smoke-guest.sh

export HB02_UTM_APP=/Volumes/UTM/UTM.app
export QEMU_IMG=$PWD/experiments/vm/tools/qemu-img

experiments/vm/prepare.sh \
  --image assets/root.raw \
  --kernel assets/Image \
  --initrd assets/initramfs-hb02 \
  --payload assets/guest-payload.sh \
  --data state/data-docsync.raw \
  --data-size 64M
```

`prepare.sh` 以 `experiments/vm` 为相对路径基准，因此它使用 `assets/...` 和 `state/...` 参数。`start.sh` 通过仓库根目录启动，因此它使用 `experiments/vm/...` 参数。

### 启动、停止并再次启动

以下命令连续执行两次。每次收到 guest handshake 后运行 `stop.sh`。第二次启动复用同一个 `data-docsync.raw`。

```sh
export HB02_START_TIMEOUT=30

experiments/vm/start.sh \
  --qemu experiments/vm/tools/qemu-system-aarch64 \
  --qemu-img experiments/vm/tools/qemu-img \
  --image experiments/vm/assets/root.raw \
  --data experiments/vm/state/data-docsync.raw \
  --kernel experiments/vm/assets/Image \
  --initrd experiments/vm/assets/initramfs-hb02 \
  --payload experiments/vm/assets/guest-payload.sh \
  --memory 512M \
  --cpus 2

rg 'HB02 guest payload|HB02_GUEST_PROBE|HB02_GUEST_READY' \
  experiments/vm/state/qemu.log
experiments/vm/stop.sh
```

## 本次修复

- `build-smoke-guest.sh` 将 ext4、JBD2、mbcache 和 CRC16 模块加入 initramfs。没有这些模块时，真实 guest 无法挂载 ext4 `/dev/vda`。
- `guest-init.sh` 在 `switch_root` 前把 `/dev`、`/proc`、`/sys` 和 `/run` 移入新根。新根保持只读，payload 使用独立的 `/run` tmpfs。
- `build-smoke-guest.sh` 将 checked-in payload 的来源、哈希和版本写入 asset manifest。`prepare.sh` 因此能验证 payload provenance。
- `experiments/vm/README.md` 使用 `prepare.sh` 实际接受的 `assets/...` 相对路径。

## 验证边界

- 结论只覆盖本机 macOS 26.6、UTM 5.0.8、QEMU 10.0.12、Alpine 3.24.3 和 kernel 6.18.58-r0 的组合。
- 无网络、无共享目录和无 QMP 的结论覆盖当前 QEMU 命令。以后新增设备或启动参数时必须重跑验证。
- 本次验证覆盖 HB-02 smoke VM，不覆盖应用层模型调用、MCP、CLI 或安装包集成。
- `run.sh self-test` 仍输出 `vm_boundary=unverified`，因为该命令只测试 frame channel 和 `os.pipe()`。真实 VM 证据来自本节的两次 QEMU 启动。

历史记录中的后续命令（现已完成）

在 arm64 Homebrew 或可复现源码构建环境完成工具安装后，先记录：

```sh
brew install qemu
qemu-system-aarch64 --version
qemu-img --version
```

再提供真实、可校验、许可明确的 ARM64 guest artifacts，并执行：

```sh
experiments/vm/prepare.sh --image path/to/guest.raw --kernel path/to/Image --initrd path/to/initramfs --payload path/to/payload.sh
experiments/vm/start.sh --image path/to/guest.raw --data experiments/vm/state/data.raw --kernel path/to/Image --initrd path/to/initramfs --payload path/to/payload.sh
```

必须从 guest 串口输出记录设备/挂载、`ip link`（无网络）、QMP/共享目录不可达、宿主文件/互联网/局域网不可访问，并写入数据盘对象后重启，比较重启前后 SHA-256；任何一项未执行都保持 blocked/unknown。
