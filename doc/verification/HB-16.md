# HB-16 模型配置与凭据存储

状态：候选实现，普通执行保持关闭；本轮完成授权编排、Keychain 实现与离线回归，未宣称真实联网模型验收。

## 实现

- `Sources/HavenboxCore/Configuration.swift` 提供提供方、模型、执行方案、本地资源及版本化摘要；未知参数（包括未声明的 temperature/reasoning）拒绝。显式 temperature 必须可解析为 finite Double 且在闭区间 `0...2`，空值、非数字、NaN、inf、负数及大于 2 均返回结构化 `ConfigurationError.invalid("temperature")`；省略时保留默认/缺省语义。
- 在线端点仅允许 HTTPS 公网主机，拒绝 loopback、私网和无协议端点；本地资源不影响在线配置。
- `KeychainCredentialStore` 使用系统 Keychain（service `com.havenbox.credentials`），数据库只保存 opaque credential reference；此候选没有内存替身。
- `WorkspaceStore.saveConfiguration/readConfiguration` 将非秘密配置写入既有 `config_revisions`，兼容性证据单独写入不可变 `compatibility_checks`，摘要变化自然使旧证据不匹配。
- Schema 从 v1 升至 v2：打开旧库时在真实 SQLite 事务中重建缺少 sequence 的 compatibility_checks，按旧 rowid 迁移并使用 AUTOINCREMENT；备份/迁移失败进入只读历史模式；已记录 running job 的事务失败重启后仍保持只读，必须从验证过的备份恢复，成功迁移可继续写入。活动回合或既有未完成迁移阻止升级；不自动重放任务。
- 配置摘要使用共享 canonical JSON（sorted keys、Set 字段显式排序、revision 与 provider/endpoint/protocol/model capabilities/parameters/tools 纳入，credential 仅 opaque revision），摘要前加 `havenbox.configuration.v2` 域分隔；保存、checker 与 compatibility 查询复用同一函数，旧摘要不再匹配。
