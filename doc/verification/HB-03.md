## User launchd job procedure

正式用户 job 由 `config/launchd/manage.sh` 生成，helper 位于 `config/launchd/hb03-helper.py`。脚本使用当前登录用户的 `gui/$(id -u)` 域，不设置 `KeepAlive`、`StartInterval` 或 `StartCalendarInterval`，并明确设置 `AbandonProcessGroup=false`；生成 plist 权限为 `0600`。helper 监视 UI PID 和 lease 文件，租约到期、UI 消失或收到 SIGTERM/SIGINT 时停止其子进程组并删除 state 文件。

实际执行的可复制命令（每个 `printf` 都真实写入一个换行；运行前创建 runtime 目录）如下：

```sh
base="${TMPDIR}/hb03-launchd"
mkdir -p "$base"
printf '%s\n' "$(python3 -c 'import time; print(time.time()+120)')" > "$base/lease"
sleep 120 & export HB03_UI_PID=$!
export HB03_LEASE_FILE="$base/lease" HB03_STATE_FILE="$base/helper.pid" HB03_RUNTIME_DIR="$base"
config/launchd/manage.sh register
config/launchd/manage.sh print
config/launchd/manage.sh kickstart
sleep 1
config/launchd/manage.sh print
config/launchd/manage.sh stop
sleep 2
config/launchd/manage.sh print
config/launchd/manage.sh unload
config/launchd/manage.sh print 2>&1
config/launchd/manage.sh cleanup
```

实际退出码和证据：`register=0`、注册后 `print=0`，输出含 `type = LaunchAgent`、`state = running`、`program = /usr/bin/python3`、`runs = 1`、`active count = 1`。注册后立即 `kickstart=0`，随后 `print=0` 显示 `state = running`、`active count = 1`、`runs = 2`，证明 kickstart 真实成功并使 job 再运行一次。`stop=0`；两秒后 `print=0` 显示 `state = not running`、`active count = 0`、`runs = 2`，state 文件已删除，说明 job 未自动重启。`unload=0`；卸载后的 `print` 返回 **113**，并输出 `Could not find service ...`；`cleanup=0`，本次生成的 plist、lease、state、stdout、stderr 和 runtime 目录均已清理。`ps -axo pid=,ppid=,pgid=,stat=,command=` 快照未发现 helper 或受控 `sleep` 残留。

`cleanup` 只删除当前 label 的 plist，以及当前 `HB03_RUNTIME_DIR` 下脚本生成的 `lease`、`helper.pid`、`stdout.log`、`stderr.log`，最后仅在目录为空时执行 `rmdir`；目录中存在用户无关文件时，`rmdir` 失败并保留该目录及其文件。它仍容忍 job 已卸载的 bootout 失败。launchd job 可重复注册/卸载；禁止对用户 LaunchAgent 使用 `sudo`。
