## 探针与真实结果

命令：`experiments/process-lifecycle/run.sh`，退出码 **0**。探针使用真实本机 Python 进程和 `/bin/ps`，记录完整 PID/PPID/PGID/STAT/command 快照；启动 UI、helper、子进程及孙进程。helper 在终止 child 前保存 PID/PGID 元数据；helper-kill 由独立 watcher 在确认 helper 死亡后读取保存的 child PGID，清理整个进程组及后代。每个场景在组清理稳定后扫描探针进程，最终 `final_probe_pids` 也纳入退出码。

| 场景 | 预期 | 实际 | 退出码 | 结果 |
|---|---|---|---:|---|
| UI 强杀 | helper 检测 UI 失联，相关进程停止 | UI、helper、子进程均 `alive:false`，后续无可见进程 | 0 | pass（本机机制） |

## launchd 用户 job 操作

README 已记录真实用户 job 的注册/卸载步骤：生成 `$HOME/Library/LaunchAgents/<label>.plist`，先用 `plutil -lint` 检查，使用 `launchctl bootstrap gui/$(id -u) "$plist"` 注册，使用 `launchctl print` 检查，使用 `launchctl bootout gui/$(id -u) "$plist"` 卸载，然后确认 `launchctl print` 失败并删除 plist。操作必须以登录用户执行，不使用 `sudo`。

本次没有注册产品 job：仓库没有正式 plist、固定 RuntimeWatchdog helper 或产品运行时，注册会变成未经授权的伪造产品能力。因而没有 `launchctl print` 产品 job 输出；“job 不自动重启任务”保持未验证。README 明确要求实际证据包括脱敏后的 `launchctl print`、`ps -axo pid,ppid,pgid,stat,command` 快照、信号命令/退出码和清理后的后代检查。
