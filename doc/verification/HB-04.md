## 实现与安全前置条件

新增 [`acp_client.py`](../../experiments/harness/kimi/acp_client.py)：固定可执行文件/摘要、环境白名单、初始化与版本拒绝、会话创建、单活动 prompt、递增 ID、乱序响应关联、协议错误与未知/重复 ID 拒绝、session/update、permission cancelled、其他反向请求 -32601、取消通知、进程组清理与 wait 回收。客户端不宣告 fs/terminal 权限，不执行工具。

读写上限：每帧 64 KiB，stdout+stderr 累计 1 MiB，发送累计 1 MiB，事件 256，挂起请求 8，默认每次 I/O 等待 15 秒；读写均非阻塞。stderr 仅计数丢弃，不持久化任意敏感日志；RemoteError 只暴露数字 code。必须在 context manager 内使用，失败路径退出时杀进程组并回收。macOS 对已退出子进程的 killpg 可能返回 EPERM：仅确认子进程已退出时容忍；仍存活则明确报告组清理失败。

新增 [`managed.toml`](../../experiments/harness/kimi/managed.toml) 与 [`protocol_probe.py`](../../experiments/harness/kimi/protocol_probe.py)：

- 入口要求显式 `--local-fixture`，不改变旧默认零 Popen 行为。
- 自建 /private/tmp 下独占 0700 HOME，配置 0600，cwd 位于同一私有目录；退出删除。不会采用用户目录、共享 HOME、符号链接 HOME。
- HOME/KIMI_CODE_HOME/XDG/TMP 指向私有目录，固定 PATH；不继承模型、代理、认证、PYTHONPATH 或 loader 环境。禁止 KIMI_CLI/KIMI_ACP/KIMI_CODE_HOME 外部覆盖，包括空值。
- KIMI_DISABLE_TELEMETRY=1、KIMI_CODE_NO_AUTO_UPDATE=1、KIMI_DISABLE_CRON=1；config 禁用 telemetry、auto_session_title、技能聚合与产品技能；不配置 MCP。
- 本机 HTTP fixture 仅监听 127.0.0.1 动态端口，合成 key 不是真实凭据；所有模型配置指向该端点。固定拒绝代理 127.0.0.1:1 是纵深措施，NO_PROXY 只允许 loopback；**不是不可绕过的 OS 防火墙**。
- fixture 实现确定性 READY、挂起用于取消、HTTP 400、部分文本后 SSE error(code=400) 四条路径；只记录请求结构，不持久化完整隐藏 system prompt。后者 HTTP 状态为 200，不能声称已发送流式文本后 HTTP 状态还能变成 400。

既有 `probe.py`、`test_probe.py`、`run.sh` **未改动**。其 `/usr/local/bin/kimi` 与 `acp --version` 属于旧元数据探针，不是新客户端部署契约；保留其默认网络关闭时全部 blocked 的安全回归，避免将本地协议 opt-in 偷换成联网授权。

### 协议完成与业务结果分离

`ACPClient.wait(prompt_id)` 现在返回 `stopReason`、`protocol_status=completed` 和独立 `business_outcome`。正常 `end_turn` 一律是 `unknown`；`cancelled` 为 `cancelled`；RPC error 仍抛 `RemoteError`。不会采信上游结果中自带的同名业务字段，也不会因文本为空判失败或因已有文本判成功。协议取消只表示协议回合取消，不保证外部副作用撤销。

本机 fixture 在单活动回合下用发送 prompt 前的请求列表位置到该 prompt 返回形成关联窗口，只在该测试作用域将已知失败汇总为 `failed`。这不是通用提供方网关：没有可信关联证据的实际提供方仍为 `unknown`；尚无业务 success 路径。新回归同时固定无证据/HTTP200 不升级 success、正常完成、取消、HTTP400、部分文本后错误及不可信业务字段不得覆盖结果。

| 本轮路径 | ACP 实值 | 客户端业务结果 | 本地探针证据与汇总 |
| --- | --- | --- | --- |
| READY 正常完成 | end_turn | unknown | 协议 pass，不声称业务 success |
| 挂起后取消 | cancelled | cancelled | 协议 pass |
| HTTP400 | end_turn | unknown | 请求窗口内 HTTP400，业务 failed，错误传播 blocked |
| 部分 READY 后 SSE error(code=400) | end_turn | unknown | HTTP200 + 流内 error，业务 failed，错误传播 blocked |

部分文本失败的真实 ACP 更新包含 `agent_message_chunk: READY`，证明非空文本也不能判成功。四次请求均无 tools；私有 HOME 删除、进程回收成功。整体仍为 `partial`，不提升提供方、网关或 VM 兼容等级。

### 上游精确补丁点（仅方案，未构建或实测补丁）

固定 commit：`472192c34c1efad89a369870eff0da0b708ce9bb`。

- [`packages/acp-server/src/session.ts:907-921`](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/session.ts#L907-L921)：`onTurnEnded` 通过 `driverFor(event.turnId)` 关联当前 prompt；`settleDriver` 内只对 `reason==='failed' && isAuthError(error)` 调用 `driver.reject(RequestError.authRequired(...))`，其他失败进入 `driver.resolve({stopReason: ...})`。补丁应在现有认证分支后、resolve 前，对一般 failed 返回与原 prompt ID 关联的 JSON-RPC error；保留认证专用错误及 cancelled/completed 行为，明确 filtered/refusal 的兼容策略，错误消息需脱敏，不直接透传提供方敏感正文。
- [`packages/acp-server/src/events-map.ts:47-76`](https://github.com/MoonshotAI/kimi-code/blob/472192c34c1efad89a369870eff0da0b708ce9bb/packages/acp-server/src/events-map.ts#L47-L76)：`turnEndReasonToStopReason` 的 `failed` 分支仅 provider.filtered 返回 refusal，其余返回 end_turn；注释也说明失败应在 JSON-RPC error 通道表达。需同步收窄函数适用范围/更新注释和映射测试，不能创造 ACP 未定义的 failed stopReason，更不能只改此映射冒充错误传播修复。

3. **历史恢复策略**：暂只允许新会话；产品恢复先重新验证版本、模型路由、文件与授权，再决定原生 load 或用户确认的摘要重建，不自动重放工具与旧审批。原生导出/重启 load/replay 实验仍 unknown。
4. **真实提供方与 VM**：需协调者批准真实模型/付费请求后执行，且在 HB-02/HB-03 的隔离环境和受限网关中重新记录行为；不将此宿主 loopback 实验标记正式离线或联网验收通过。
