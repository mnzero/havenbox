## 实现

- `experiments/harness/pi/probe.py` 是可复现 Python 探针，逐条输出 JSONL 结果记录；批准版本固定为 `PINNED_VERSION = "1.3.0"`，版本变更必须修改并审核代码。版本门禁失败退出 2，发生在任何 RPC 启动之前；旧 `--expected-version` 参数由 argparse 拒绝并退出 2。
- `experiments/harness/pi/run.sh` 从仓库根目录定位探针。
- 子进程以隔离临时目录为 cwd，并关闭 MCP、扩展、skills、上下文文件和 session；探针 stdout 只消费 JSONL，stderr 单独收集。
- 子进程协议使用 `id` 关联 response，保留暂未匹配的记录，支持原 bash 终态先于或晚于 abort 应答到达。
- 取消使用带 PID 文件的 `sleep 30` 子进程，先确认存活，再发送 abort；必须同时获得 abort 应答、原 bash 请求的取消终态和 PID 消失证据。缺少任意证据判 fail，使探针非零退出；检查在 Pi 清理退出之前完成，不能靠关闭 Pi 获得取消通过。
- `experiments/harness/pi/test_probe.py` 包含版本不匹配、参数绕过、版本命令失败、仅 abort 应答、错误请求 ID、正常完成冒充取消、取消终态但进程仍活着，以及响应两种顺序的回归。测试中的假 transport/PID 观测只用于回归，不当作真实取消证据。

## 执行记录

```sh
python3 -m unittest discover -s experiments/harness/pi -v
python3 -m py_compile experiments/harness/pi/probe.py experiments/harness/pi/test_probe.py
sh -n experiments/harness/pi/run.sh
experiments/harness/pi/run.sh > experiments/harness/pi/last-run.jsonl
```

本次四条命令均退出 0，8 项回归测试全部通过（取消应答先后顺序以两个子用例覆盖）。真实探针输出保存在 `experiments/harness/pi/last-run.jsonl`：共 11 条，9 条 pass、1 条 unknown（MCP）、1 条 blocked（历史恢复），没有 fail。版本不匹配与旧参数绕过的负向回归均验证退出 2 且从未启动 RPC；整次探针退出 0 仅表示已覆盖的宿主 RPC 检查无 fail，不表示 blocked/unknown 项通过。`get_state` 暴露了当前默认模型元数据，但本次没有发送 prompt，因此不把模型可用性当作模型调用通过。Python LSP 未提供完整诊断，本次以实际编译和回归执行作为验证依据。

## 验证边界

HB-02 的真实 ARM64 VM、只读根盘和独立可写数据盘证据仍只覆盖 VM 边界；它没有证明 Pi 应用层模型、MCP 或 CLI 集成。Pi RPC 本次是在宿主机运行，未声称已经在 HB-02 guest 内运行，也未修改 HB-01/HB-02/HB-03 文件。取消 PID 检查依赖同一宿主的进程可见性，只证明此次直接 bash/sleep 取消；不能推导远程 VM、模型流或工具桥取消可靠。临时 cwd 不等于完全隔离用户配置：本次 `get_state` 和 `get_commands` 仍可见宿主模型配置与全局 prompt 元数据。

Pi 文档定义的 RPC 仍要求客户端处理启动失败、意外退出、stderr、超时和取消；本探针覆盖了 stderr 分流、响应超时和退出清理，但未覆盖 provider streaming、`prompt`/`agent_settled`、模型实际生成、扩展 UI 审批或跨进程重启恢复。后续要判定这些项目，必须先提供固定 provider/model、审批策略、受审 MCP bridge 和持久 session 目录，并把它们作为显式输入记录。

`get_commands` 返回的是全局 prompt 命令清单，不能当作 MCP 工具发现或授权证据；因此 MCP 项保持 unknown。
