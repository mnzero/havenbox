日期：2026-10-24。范围依据 HB-02 真实 VM、HB-03 生命周期证据、PRD F18/F20/F21/F23/F26/F28、S13/S15/S18/S19。工作区只新增 `experiments/harness/dsh/` 和本报告，未修改 HB-01/HB-02/HB-03。

## 结论

**blocked/unknown，不能授予 dsh 组合通过。** 探针使用受管 `runtime-manifest.json` 中固定的 launcher 和 lockfile 路径，完全忽略 `HB06_DSH_BIN` 与 PATH 中的 `dsh`。当前 worktree 没有 runtime 制品、lockfile 和批准的 sha256，因此探针明确返回 `blocked`，不会启动伪 launcher；真实运行时到位并通过版本、commit、lockfile/hash 校验后，才允许启动 launcher 发送最小 `initialize` JSON-RPC 请求。

上游事实来自该 commit 的 `docs/architecture.md`、`packages/bundle/sdk-minimal/README.md`、`packages/sdk/protocol/src/types.ts` 和 `packages/sdk/server/src/server.ts`。源码显示 SDK 是 stdio NDJSON JSON-RPC，初始化显式接收 `cwd/provider/model`，`approvalRequests` 默认关闭；协议没有 `session/cancel` 方法，取消需由宿主撤销授权并终止受控进程组。`sdk-minimal` 的默认树包含本地 shell、`danger-full-access` sandbox、自动 compaction、LLM retry 和 JSONL session persistence；它省略 telemetry/base settings，但不能由“省略 telemetry”推导网络或模型调用已受控。

## 固定探针

```sh
python3 experiments/harness/dsh/probe.py --json /tmp/hb06-dsh-result.json
```

探针固定 `runtime-manifest.json` 指定的 `runtime/bin/dsh`、`runtime/package-lock.json`、版本、commit、Node 要求和两项 sha256。它不读取 `HB06_DSH_BIN`，也不调用 `shutil.which("dsh")`；任意覆盖值不能改变受管路径。launcher、lockfile 或任一批准 hash 缺失/不匹配时，结果为 `blocked`、退出码 3，且不启动子进程；全部校验通过后才创建独立 `DSH_HOME`，设置遥测关闭和 sentinel Key，启动真实 launcher 并发送一个最小 `initialize` JSON-RPC 请求。

本次实际运行：受管 launcher、lockfile 与批准 hash 均缺失，结果为 `blocked`，未启动子进程、未发送 JSON-RPC、未触发网络或模型请求；`homeCreated=false`、`homeRemoved=false`、`environment=null`，独立 home 从未创建（不是创建后清理）。`HB06_DSH_BIN` 即使设置也不影响结果。网络/遥测/Key 持久化/审批/取消/错误/恢复证据仍保持未验证，禁止以伪 launcher 或静态记录冒充通过。

## 所需补丁与恢复策略

1. 使用 pinned runtime artifact，并保存平台、Node（上游要求 `>=24.9.0`）、launcher 和依赖 lockfile 哈希；禁止未哈希的全局 `dsh`。
2. 在 `sdk-minimal` 上加 profile patch：移除 persistent bash/PTY 或改接宿主受限工具；将 sandbox 从 `danger-full-access` 改为 VM 内固定 workspace；明确关闭 MCP 外联、telemetry、jobs/subagents 和自动 provider fallback。
3. SDK client 对 `approval/request` 实施默认拒绝、一次性授权、session 绑定和 TTL；取消时先撤销授权，再杀受控 runtime 进程组，禁止把 JSON-RPC timeout 当作已停止。
4. 启动前通过 HB-02 真实 VM 检查无网卡、无共享目录、根盘只读和独立数据盘；模型请求只到宿主批准网关。首个请求前绑定 provider/model/端点/发送范围并取得授权。
5. 恢复只加载经过 schema、路径、模型/profile、权限和会话归属校验的记录；重新建立模型授权，不自动 `resume` 未完成工具操作，不重放任何旧 approval。

## 复审修复与探针回归

- `create_home()` 和子进程 `env` 的建立严格位于全部固定 version/commit/lockfile 路径、制品可用性及两项 hash 校验通过之后；缺制品、hash 不匹配及版本不匹配均不创建 home、不复制环境、不调用 RPC。
- `contract.json.adapterVersion` 与实现常量一致，为 `hb06-dsh-probe-2`，由回归断言锁定。
- JSON-RPC 使用非阻塞管道、`selectors` 和单一 monotonic 截止时间（默认 5 秒），不是在阻塞 `readline()` 外检查时钟；stdin 写入、stdout/stderr 读取均受截止时间约束，stdout 与 stderr 合计上限 65536 字节（至多额外读取 1 字节检测越界）。完整行、EOF、超时或输出越界后终止本次新建进程组并关闭管道，等待 launcher 回收另有 2 秒上限，不执行无限 drain。
- `test_probe.py` 的 7 项测试覆盖无输出、部分行无换行、stdout/stderr 输出超限、完整响应不等待 stderr EOF、超时杀后代进程、校验失败不建立环境及 contract 版本一致性。所有 launcher 均为 **测试替身，只证明探针行为，绝非 dsh 实测**。
- 首次回归发现新建 Python launcher 在本机首次执行有启动延迟，0.3 秒测试预算导致响应/输出上限用例误超时；测试预算改为 2 秒，增加 ready 标记验证替身及后代实际启动，避免以未启动进程的超时假充覆盖。
