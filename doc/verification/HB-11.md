## 结论

`hb11-candidate-16` 已形成最小完整的真实闭环：`RuntimeManager → launchd → helper → QEMU/HVF → guest init → Rust supervisor → 固定 synthetic task`。所有通过项都来自真实 ARM64 guest，没有使用 mock 替代隔离证据。复验命令和预期输出保存在 [HB-11 真实运行时复验](../runbooks/hb11-real-runtime.md)。

## 已实现且真实执行的边界

- `hb.channel.v1` 使用 68-byte header，校验 channel、方向、epoch、request UUID、payload 长度与 SHA-256；严格 JSON 拒绝重复 key、过深嵌套和未知/错误方向消息。control/file/inference 使用三条独立 virtio-serial port，并有有界队列与写 deadline。
- host 资产从根目录逐级 `openat(O_NOFOLLOW)`，拒绝符号链接组件、可写父目录、hardlink、权限或哈希漂移。helper 对 config、QEMU launcher、固定 QEMU framework、kernel、initrd、root 和 data 保持已打开 FD，启动前重新核对哈希与 pathname inode。
- QEMU launcher 不再解析 `/Applications/UTM.app` 或继承任意 UTM 根路径。helper 只注入经过哈希校验的 `HB02_QEMU_SYSTEM_FRAMEWORK=<absolute path>`。在 `/Applications/UTM.app` 不存在时，正常和 lease-expiry 产品链均成功。
- launchd job 使用 `AbandonProcessGroup=false`；helper 在所有可处理退出路径终止并 reap QEMU、删除 config/plist/FIFO/socket，并自卸载 job。FIFO 设置 `F_SETNOSIGPIPE`，UI、helper、QEMU 分别被 `SIGKILL` 后均无 job、helper/QEMU 或控制文件残留。
- guest init 固定挂载两块 virtio block 盘、proc/sys/dev/cgroup/tmp，等待并核对三条 virtio port；supervisor 拒绝完整 mount/block/network inventory 漂移。
- 单线程 broker 在 child exec 前配置并回读 cgroup memory/swap/pids/cpu，先把 child 写入 `cgroup.procs` 再放行。child 关闭继承 FD，创建 mount/network/IPC namespace，按角色 chroot，清 capability/groups，设置 rlimit 和 `no_new_privs`，降到 UID/GID 10001 或 10002，安装固定 AArch64 seccomp 后只 exec 固定 BusyBox 合成脚本。
- harness chroot 不包含 `/input`、`/data`、`/sessions`、`/worker` 或设备节点；worker 看不到 `/context`、`/history`，input/context 写入失败。正常任务只在各自允许目录产生结果，原输入不变。
- 任一日志流超过 1 MiB、控制断开、协议错误或 lease 到期均触发 `cgroup.kill`、leader reap，并等待 `cgroup.events` 的 `populated 0`。guest 在发送 `Stopped` 前对 data 执行 `syncfs`，避免 QEMU 随即退出导致已确认结果丢失。
- data ext4 启用 project quota；worker 启动前设置并回读 project ID、block/inode hard limit 与 `PROJINHERIT`，结束后恢复 output 所有权。此轮没有故意耗尽 project block/inode quota。

## 尚未验证或未完成

1. QEMU 主 framework 副本已哈希绑定，但它通过 launcher 的固定 rpath 从只读、已公证 UTM 5.0.8 挂载包加载约 1 GiB sibling frameworks；这些 sibling 文件尚未逐项进入 runtime manifest/SBOM。DMG hash、只读 mount、Developer ID/notarization 检查降低了漂移风险，但不是逐文件内容绑定。
2. QEMU、kernel、initrd/root 仍由外部程序按 pathname 重新打开。helper 在 `posix_spawn` 前核对已打开 inode 与 pathname，受管只读目录是正式部署仍需满足的前提；系统没有把这些内容通过 FD 直接传给 QEMU。
3. memory、pids、CPU 与 project quota 已配置/回读，输出上限已真实触发；本轮没有分别制造 OOM、pids.max、CPU throttling、project block/inode 超限，也没有覆盖稀疏文件、rename/hardlink、重启后的 quota 计量。
4. synthetic profile 证明固定隔离机制，不证明真实 Kimi/Pi/dsh、Node/Python、模型、MCP、文件导入或推理网关组合。最小 macOS 版本与 16 GiB 参考机性能也未测。
5. HB-31 功能、HB-32 安全和 HB-33 发布资格未执行；依赖许可证、完整 SBOM 与分发签名仍未闭合。

判定：`hb11-candidate-16` 是已经过真实 VM 行为验证的固定 synthetic runtime 候选，但保留上述边界，普通资格与 ValidationRunGrant 继续关闭。
